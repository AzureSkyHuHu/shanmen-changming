# Combat definition protocol v1

This directory owns only TypeScript contracts. It does **not** execute combat. Import the public protocol from `./index.ts`; import authored data from `src/content/definitions/index.ts`. The source of truth is the frozen design §10–15 and DD06–09. Every authored number is an **unbalanced tuning baseline**.

## Units and identity

- Simulation time is integral ticks at 20 Hz. Distances use integral world units. Resource/health/force values are integer units. Ratios use basis points: 10,000 = 100%. All products need checked integer arithmetic before floor division.
- Definition IDs are immutable ASCII names such as `skill.liuhen-jian`, `node.sword.liuhen`, `talent.humai`. Translations never act as IDs. Runtime source IDs use the kernel's namespaced sequence format, e.g. `entity:1` and `instance:42`.
- A `SourceOwner` identifies the original definition, entity, installation instance, creation sequence, lifecycle boundary and duration. Every modifier, trigger, status, charge, cooldown, cast-history record and stored-force contribution must retain this ownership. Remove by `sourceInstanceId`, never by translated name.
- `lifecycleScope` sets the latest removal boundary. `duration` can expire sooner. A run-owned effect with a 100-tick duration expires after five seconds or at run cleanup, whichever occurs first. Infinite character effects still end when their owner dies or the source is uninstalled.
- `ModifierSpec.modifierId` is unique within a definition. Runtime modifier identity is `(sourceInstanceId, modifierId)`. Dynamic modifier conditions are evaluated during stat queries, rather than only on installation. Query tags use AND matching; an empty modifier tag list matches all queries. Invalidate cached stats when shield/status/condition inputs change.

## Data interpretation contract

Conditions and selectors are closed discriminated unions. `eventSource` in a tag condition refers to the immutable originating action's tag set. `actor` is the installed source holder; `target` is the current resolved target. `eventActor` and `eventTarget` selectors refer to the immutable event participants. `intent` is the original action target. The action's explicit `targetTeam` and `rangeUnits` are checked at reservation and again at commit; a target selector never grants permission to heal enemies or attack allies. `self` is the installed holder (the bearer for a status); `statusSource` is the original status applier. All selectors revalidate living/legal recipients when executed; only the `rescue` operation may target a downed ally. Stable entity IDs break selection ties.

`eventScope: owner` listens to the holder's actions, or changes affecting the holder for defensive/life events. `allies` listens to living members of the holder's team, including the holder unless a condition excludes them. `team` listens once for the run-owned team source, never once per party member. Event fields are readonly snapshots; a missing field makes a condition false, including `ne` and a flag expecting false.

Ordered effect arrays are small data programs. `consumeStatus` emits an actual-consumption event and binds a nonnegative count to its local `resultKey`. If the minimum is unavailable, it consumes nothing and binds zero. A later `Amount.kind: consumed` in the same list reads only this count. Delayed zone programs and trigger programs have separate result bindings. No expression strings, callbacks, arbitrary state paths or content-defined executors are allowed.

`damage` uses the declared attack snapshot, hit-live defense, explicit armor penetration and floor rounding. DOT attack comes from its original applier's application snapshot, even though its target selector is the status bearer. Proc damage cannot double-apply the original incoming damage formula. Requested damage, actual shield absorption and actual health loss are separate event values. Shield and overheal conversions read only their specified event fields and apply their own cap.

`applyStatus` uses the target status definition's encounter scope, identity, stack policy and explicit duration. Remove expired instances **before** processing periodic ticks; expiration is exclusive. Refresh merges only the selected identity, extension clamps to its duration ceiling, independent policies retain distinct source instances, and strongest-value selection retains losing source contributions for later recovery. Stacked stat/periodic contributions scale linearly by accepted stacks before global stat caps. Strongest magnitude is the resolved contribution at installation; equal values follow the declared tie policy and then source creation sequence. `actionLock` and `resistancePolicy` specify control semantics without checking translated status names.

Modifier evaluation order remains base + flat, shared additive percentage group, independent multiply factors, min/max limits, then floor. A `minimum` modifier is a lower bound; `maximum` is an upper bound. Stat safety caps belong to the engine policy, not arbitrary content buckets.

`actionRules` filter original action tags with AND matching and adjust the authoritative action before reservation/commit. Cost discounts clamp at their declared minimum, and timing/range adjustments cannot produce negative final values. `statusDurationTicks` adjusts finite durations of shields/statuses created by matching actions. Damage bonuses enter the common additive damage bucket. Chain targets must be distinct; chain effects never emit another cast event. Summon-tagged maximum-health modifiers affect the summon calculation, not the summoner's untagged health query.

`augmentNextAction` is installed under its source with a finite duration and source-owned charges. Multi-target installation shares its `uses` budget across recipients, rather than creating `uses × party size` charges. Charges are consumed only by committed qualifying actions. `storeForce` only records real hostile shield absorption; all sources share the holder's capped force ledger. `releaseForce` drains accepted stored force once, emits one `force.released` event when positive, and does not reinterpret original incoming damage as another offensive base.

`recordCast` accepts only genuinely committed, paid, direct casts. The effect writes its source-owned bounded/windowed history and then emits `castHistory.recorded`, carrying frozen distinct-caster and distinct-school counts. The triggering cast is included. This separate event prevents same-event listeners from observing partially updated state. Root/parent provenance persists. `event.differentCaster` and `event.differentSchool` compare the current genuine cast to the previous direct cast in the relevant source's observed stream.

`preventDowned` operates only in the fixed pre-downed window and respects activation count/ICD. `rescue` affects Downed, never Dead, and applies a recovery lock. Neither creates a second death settlement or reward. `zone`, `move`, and `summon` are specified but currently blocked. A zone is placed at an anchor once; its child selector enumerates recipients each period. Paper decoys are temporary threat actors, never full disciples.

## Trigger safety and determinism

On event publication, freeze all eligible triggers before executing any. Sort by phase, event sequence, priority, holder ID, source creation sequence and definition effect index. New installations cannot listen retroactively. Derived effects drain the deterministic queue after the originating ordered program completes; they still revalidate recipients, so poison renewal cannot revive a target killed by the detonation.

Default indirect-family allowlists are empty. Specific follow-up events such as `force.released` and `castHistory.recorded` opt into exact originating proc families. A family cannot listen recursively to itself. `oncePerRoot`, `perTarget`, positive activation bounds and ICD are independent restrictions; a per-target ICD key includes target ID. Team effects use a single run-source budget and highest-value aura contribution. Root depth ≤8 and derived-effect budget ≤64 are hard upper bounds, not multiplied per listener. Budget exhaustion truncates later derived work without rerolling randomness. Budgets, source charges, ICDs and root provenance must survive save/load.

## Verification boundary

`validateCombatStructure(unknown)` is the strict JSON/data trust boundary. It rejects unknown keys, unknown operations, invalid integer bounds, accessors, inherited objects, sparse arrays and excessive nesting. `validateCombatCatalog` then checks references, exact capability manifests, scope leaks, local result binding, tree cycles and all legal five-point subsets, source reachability and locale parameters.

Authoring mode only certifies **static integrity**. Runtime mode additionally requires `implementation: verified` and an explicit `supportedCapabilities` allowlist owned by a tested executor. None of the current entries are verified/playable. A content label alone never enables an unsupported operation. `testScenarioIds` are required scenario identifiers for future positive, invalid-prerequisite, and cleanup/restore executor cases; they are **not claims that those behavioral tests exist or pass**.

No content hash or asset manifest is presented as production-ready: semantic `presentationKey` values are reserved identifiers, not verified assets. The complete package has 24 skills, 36 tree nodes, 4 trees, 12 named run talents, 4 builds, 9 statuses and 1 blocked summon. The other 36 of the 48 target run cards remain an explicit authoring backlog. Scope and functional-category counts are independent; both complete-catalog constraints are checked when the count reaches 48.
