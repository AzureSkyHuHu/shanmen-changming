# v9 内部有限恢复准入

本片增加独立的有限准入接口，保留既有 `.3` 记录型命令/推进入口的行为，不注册 codec、Session 或界面。

普通完整候选必须有受支持的容量推导并满足各维度。已有未来余量不足的世界仅能借助真实保留义务的终止证据恢复：前后实际硬上限满足，各合成维度在上限内或不增加，并核对取消、付款、终态、历史回执、疗伤效果及完整遗产转移。单独删除所有者不构成释放。

自动生产退休后不再保留完整历史。仅凭新日志通知无法证明工作或付款，因此不足状态下的无固定记录自动终止，必须与同源正常/无可选增长的真实单刻完整结果精确相同。该罕见恢复路径的重算不调用容量准入自身。命令驱动取消仍有固定回执可核对。

推进先尝试正常顺序；若无法准入，从同一个未改变边界重新准备关闭自动开工和维护续费的候选，防止可选增长挡住生命周期恢复。仍失败时返回上一完整状态和临时停止信息，不写入额外暂停、诊断或失败回执，不改变随机流、寻路或资源。

## 明确限制

- 教学没有直接取消指令，有限无可选续行证明尚未完成。新有限接口明确拒绝新授课与已有活动授课来源，旧记录型 `.3` 接口保留原行为。这不是面向玩家的最终功能策略
- 对本身违反旧领域记录余量规则的来源不放宽校验。恢复例外只适用于内部支持、实际硬上限合格但合成未来预算不足的边界
- 完整候选比较只针对该入口生成的即时边界；无固定记录的自动终止不接受任意跨多个刻或混合命令的端点代替真实单刻证明
- 当前是严格性能基线，无快路、无20Hz或3倍速流畅承诺；没有将测试通过当作完整游戏验收

## 已测性能基线（2026-10-02，dot 环境）

命令：`node tools/benchmark-v9-runtime.mjs --samples=20`。每行2次预热、20次取样，夹具构造约5.67秒不计入测量。原记录型与新有限入口的结果一致性在每次测量检查。单刻/20刻实际推进数分别记录，寿尽暂停后请求20刻实际仅推进1刻。

严格入口单刻 p50 / p95 / 最大耗时（毫秒）：

- 新世界空闲：18.19 / 19.53 / 21.03
- 实际制药后的疗伤：37.91 / 50.25 / 98.04
- 三人混合工作：40.55 / 47.02 / 49.47
- 256条真实修炼指令历史：78.37 / 91.48 / 138.09
- 月结边界：17.20 / 20.09 / 20.27
- 寿尽边界：17.36 / 19.96 / 20.71
- 接近容量的真实恢复：170.96 / 181.41 / 183.63

20刻严格批次的 p50 / p95：空闲166.40 / 197.16，疗伤368.99 / 396.92，混合423.13 / 463.99，历史778.11 / 800.71。每单刻调用2次完整容量查询，每20刻批次21次，批内沿用前一评估而不重复查询前态。

结论：历史负载单刻超过1倍速50毫秒预算，混合工作也没有足够渲染余量；3倍速更未达到要求。这是玩家入口启用前的性能阻塞。下一步保留严格入口作为差分基准，在调用内持有隔离状态，仅对已证明的标量空闲刻提供精确增量路径；活动工作仍需另外优化验证，不能用空闲快路成绩替代。

性能夹具真实执行建筑、研究、药物、工作和生命周期，但充足基础库存、某些无事发生月内边界以及诊断字节压力均明确标为测试准备；不是36弟子/150年/移动端的完整性能验收。测试与完整构建最终结果另见开发状态。
