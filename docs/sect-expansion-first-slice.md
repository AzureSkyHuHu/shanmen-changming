# 宗门扩建首个可玩切片：v9 候选方案

日期：2026-10-01。状态：源码核对后的实施建议，尚未实现或验证。本文只新增计划，不修改冻结设计包、不切换默认版本，也不代表测试、浏览器或发布通过。

## 1. 先做哪一条循环

**建议：采木采石 → 建藏经阁 → 取得研究材料 → 研究基础药理 → 建丹房 → 制作并实际使用伤药 → 研究替代药方 → 升级、搬迁丹房。**

目标是让摆放、通行、劳力、研究、产品和人物状态真实相连。第一批仅含两类新建筑、两个研究节点、五个新配方，以及丹房的一次功能升级；不做空的 14/16/36 目录凑数。

- 原始依据：[DD-02](engineering-plan/02-detailed-design/02-world-economy.md)、[DD-03](engineering-plan/02-detailed-design/03-agents-navigation.md)、[设计源 §7–8](engineering-plan/source/game-design.md#s07)、[REQ-002/006/007/008](engineering-plan/00-overview/requirements.md)、[完整验收路线图](full-game-acceptance-roadmap.md)
- 用户授权的是继续完成原游戏。14 类建筑、最多三级、16 研究、36 配方属于原设计的建议基线；本文件的名字、价格、工时、维护方式、资源来源和首批顺序均为待实测的设计假设，不宣称用户逐项确认
- 当前默认仍 v7；v8 五路线 G1 的完整退出预算、恢复和真实浏览器关口通过前，仅允许独立候选开发。v9 不绕过这些关口抢先接入实际存档或预览
- 首片不包括战斗服药、医舍系统、14 类全三级、人口扩容、交易、季节、拆除回收。它们仍在完整路线图内；宗门伤药不能冒充有限战斗消耗品已完成

## 2. 必须承认的现状

| 实际边界 | 对首片的约束 |
| --- | --- |
| `world/create-world.ts`、`create-world-v8.ts` 的八个建筑是可步行坐标；`WorldBuilding` 无占地、入口、等级 | 中央道路上有工坊、膳堂、仓库等，不能原地把坐标变为阻路建筑实体 |
| `economy/production.ts` 使用固定 `getRecipe`、按建筑坐标移动/工作/交付，已有工位、有效工时、预留和取消 | 复用成熟事务；先增加配方上下文与入口查询，不另抄一套生产器 |
| `economy/types.ts` 只有 wood/stone/herbs/grain/meal/plank 六资源、四种配方工位 | 不追加全局 `RESOURCE_IDS`；否则旧存档、培养、远征及容量证明同时变义 |
| 六个现有配方可持续产木、草药、粮食、口粮、木板；mine/spirit-vein 只是站点 | 初始 12 石头不是可持续石源；现状没有灵石、心得生产或研究准入 |
| `cultivation/v3` 的伤势为真实 0–100 值；休养每月基础减伤 8，突破预览使用伤势 | 伤药必须提交真实伤势变化、重算风险；不能只增库存或播放治疗动画 |
| `kernel/save-v8.ts`、`platform/save-codec.ts`、`application/world-engine.ts` 严格分派版本 | 不能把 v9 字段塞进 v8 后沿用 v8 校验；不能失败后降级读取 |
| `world/expedition-exit-budget.ts` 的证书绑定 candidate-2、旧六资源及特定退出路径 | 即使新物品不进远征背包，建筑/研究在返程经营刻也会改变字节与义务，必须另证 |

现有初始人物没有按原文设置受伤长者。首片可在**新 v9 开局**的已注册角色初值中给长者 25 伤势以演示照护；这是新增候选参数。迁移旧档绝不制造伤势。验证真实远征返程伤势的疗效另设用例。

## 3. 最小内容与经济闭环

以下整数是第一轮可复现夹具值，不是平衡结论。工时单位为固定经营 tick；旅行、等待、暂停和战斗 tick 均不累计有效工时。

### 建筑与研究

| 定义 | 首次材料 / 有效工时 | 真正功能 |
| --- | --- | --- |
| 藏经阁 L1 | 木 8、石 4、木板 4 / 320 | 一个共享岗位：整理基础心得或推进一项研究，两者竞争工位 |
| 丹房 L1，需基础药理 | 木 8、石 4、木板 4 / 320 | 一个制药岗位，开放基础伤药 |
| 丹房 L1→L2，需药性配伍 | 石 6、木板 6 / 400 | 保留原药方，新增不用粮食的替代方；不是全产量翻倍 |
| 基础药理，无研究前置 | 基础心得 2、灵石 2 / 240 | 解锁丹房 L1 和伤药配方 |
| 药性配伍，前置基础药理 | 基础心得 4、灵石 4 / 400 | 解锁丹房 L2 与替代方 |

两种新建筑先用 2×2 非通行占地，旋转仅 0/90/180/270 度，一个明确的外侧入口/排队点；入口和工作席位是不同令牌。研究最多一个进行中的项目；解锁永久属于宗门，拆改或停用藏经阁不撤销已完成研究。

### 可持续来源和真实产品

| 新配方 | 工位 | 投入 → 产出 | 工时 / 准入 |
| --- | --- | --- | --- |
| 采石 `gather.stone.v9` | 已有矿点 | 木 1 → 石 3 | 160 / 初始可用 |
| 采灵 `extract.spirit-stone.v9` | 已有灵脉采集点 | 石 2、草药 1 → 灵石 1 | 240 / 初始可用 |
| 整理基础心得 `study.basic-insight.v9` | 藏经阁 L1 | 木板 1、草药 2 → 基础心得 1 | 240 / 不依赖待研究节点 |
| 制伤药 `craft.wound-powder.v9` | 丹房 L1+ | 草药 3、粮食 1 → 伤药 1 | 160 / 基础药理 |
| 草木替代方 `craft.wound-powder-alt.v9` | 丹房 L2 | 草药 5、木 2 → 伤药 1 | 200 / 药性配伍 |

- 灵石是物品；灵气仍不是库存通货。低阶“基础心得”是可重复研究材料，不等于无限生成高阶稀有机缘、师承知识或永久树点。材料整理和有耗材采灵是本片提出的保底来源，原文没有确定这些配方
- 两种研究材料初始为 0；没有按现实时间发钱、重复领取研究奖励、卖回退款或读档赠送。木/草药采集 → 石/木板 → 研究材料的每一轮均实际占人、占岗位、耗材、运输；研究和维护是持续消耗端
- 低效觅粮原路保留，不要求先付口粮；研究不消耗口粮。替代伤药方保留粮食紧缺时的选择。核心必须在开始和提交时检查研究/建筑等级，手动及自动生产都不能绕过
- 原六配方目录原样复用，候选目录共 11 配方；原八站点不能全计为原设计 14 类建筑，其中 forest/mine/spirit-vein 是资源地点，灵田当前还与药圃共用工位

### 伤药的最小实际用途

使用命令选择一名在宗门、存活、有伤势且没有远征/闭关/授业/其他任务占用的人。预留一份伤药，走到仓库入口并完成 40 个护理 tick 后，原子扣药并以注册 `reduceInjury(20)` 原语将伤势降至 `max(0, injury−20)`。这不是战斗 HP 回复，不复活、不延寿、不免除待决死亡。

患者可处于休养状态，不要求其有成年劳动资格；护理期间不得同时生产、研究、施工或出征。若月度休养先把伤势降到 0，护理取消并释放药物，不无效消耗。死亡、离开、取消、读档、重复点击均只能结算一次。结果展示用前/用后伤势和重新计算的突破风险；不宣称当前不存在的“伤势自动决定 canWork”规则已经实现。

## 4. 空间、施工和经营事务

### 放置和开工

1. `blueprint.place` 只建立有界、可取消的草图；显示占地、入口、材料、工时和下一维护日期。缺料草图不预留不存在的资源，也不改变通行；但独占该草图区域的建设申请
2. `construction.start` 再验当前地形、重叠、入口和预算，锁定配方版本/价格/材料表；整笔预留成功才分配工人和启用施工碰撞。拒绝时不消费 ID、材料或随机流
3. 禁止占水、既有道路、其他占地、任何存活/待决人物当前格、旧站点及所有入口。候选导航图须让每位在家人物、仓库、基础觅粮/采木/采药/采石点、已有可用入口仍互达；不能只检验新建筑入口
4. 开始/完工/搬迁提交均复核空间。地图原始 walkable 不被建筑覆盖写死；有效通行为基础地块与权威占地的交集。成功改变占地才递增 navVersion，旧路线按预算失效重算

### 工作、取消、搬迁和升级

- 施工工人先到仓库取材，再到外侧施工入口；途中不加工时。在途材料仍属于订单预留，不另加 owned。首片一工人、一席位，复用稳定排序与每 tick 寻路预算，所有任务共用该预算而非每模块各取四次
- 建造/升级分两个耗材检查点：一半工时消耗各材料 `ceil(cost/2)`，完工消耗其余；零数量行剔除。账本记录 consumed 和 remainingReservation，各检查点原子提交并可精确重试
- 取消只释放未消耗预留；已耗部分不退，草图/席位/工人/地块预约一起释放。完成后不能再走取消退款。取消不传送人物；保留最后真实可达格，没有安全位置就保留原边界并报错
- 搬迁只针对本片新建筑：空闲后停用，旧占地仍存在，目标先软预约；木 2、200 工时，工人实际走旧入口→新入口。提交才原子交换占地与入口、恢复允许的功能、使路径失效；目标被人占住则等待/取消，不能压人或传送
- 搬迁取消恢复旧位置；升级取消恢复旧等级，均保留已消耗成本。开始操作时有生产、研究或入口令牌就拒绝，提示先正常取消/结束任务，不暗中丢失工作
- 升级全程旧建筑停产，不同时计算两级收益；首片升级不扩占地。完成后一个实体 ID、一个维护计时器、一个实际等级；重复确认不能复制建筑或席位
- 开始施工、研究、生产或护理前，v9 的统一占用查询检查生产 assignment、培养/远征锁及新任务 owner。`assignmentTransactionId` 仍只表示旧生产，不塞入无法由旧校验解析的研究/施工 ID
- 研究开始一次性预留全部成本，到藏经阁并占席才加工时；完成时扣成本、登记节点和解锁一起提交，取消释放全部未耗预留。新生产沿用到仓库才扣投入/入产出的规则；额外库存满时保留可取消订单并显示缺口，不丢药、不先扣原料

### 最小维护

藏经阁 L1、丹房 L1 每经营月各耗木 1；丹房 L2 耗木 2、草药 1。建造费包含首个经营月，首次维护 `completedCalendarTick + 1200`；首次启用和以后周期都记录来源，不能先运行再倒扣。

到期仅使用 available，不能挪用其他任务预留。不足则停用并显示缺口，保留未耗任务预留；不突然摧毁建筑或积累无法偿还的欠款。补齐后通过明确恢复命令支付一次、开始新周期。搬迁继承原到期时刻，不能通过搬迁免维护；升级期间仍按旧等级处理到期，成功后下一个周期才用新费率。完成研究后仍可用解锁，但停用丹房不能生产。

维护按建筑记录有界的最近状态及累计计数，不每 tick 写日志。提前显示下一检查点、库存、已预留和净缺口。是否需要更复杂耐久/维修留待后续切片，不能给未实现的损坏状态虚构数值。

## 5. v9 数据和复用端口

推荐 `saveVersion:9`、`simulationVersion:0.9.0`，另注册只用于候选的宗门内容身份。**不修改旧六资源枚举、不替换 v7/v8 配方、不修改已注册身份的指纹算法。**

### 最小新增权威状态

- `sectExpansion.schemaVersion:1`：独立的建筑空间/等级记录、草图/订单、研究状态、护理记录、有界事务回执和额外库存
- `sectExpansion.stock` 仅三种新资源：`spirit-stone`、`basic-insight`、`wound-powder`。原 `world.inventory` 六资源继续是唯一原材料权威；不复制木石余额，不把新物品塞进远征 ResourceLine
- 成本/产出使用有判别标签的 `{ledger:'base'|'sect', resourceId, quantity}`；从纯泛型预留原语复用计算，两本账的多项扣入在同一个 detached World candidate 中提交。任何一侧溢出、取消证明或保存预算失败，两侧全部回滚
- 建筑沿用实体 ID。额外空间记录分 `legacy-point` 与 `placed`：旧八点入口等于原坐标、空实体占地；新建筑保存锚点、朝向、目录 ID、等级，占地和入口由不可变目录推导并校验。新建筑不能伪称 legacy-point；旧站点首片不可搬迁/升级
- 不把已有 `builds` 永久构筑域当建筑系统。新命令统一 `sect.command`，域内区分 blueprint/construction/research/care；结果/事件用 v9 合同，避免污染旧 Command/DomainEvent 的可接受集合
- 新完成回执证明材料来源、占用、有效工时、内容版本和唯一结果；研究解锁须反向指向一次真实完成记录，不能只信 `unlocks` 字符串。伤药用量和伤势变动同属一个护理事务
- 候选硬边界：所有活跃生产/施工/研究/护理合计不超过 36；未开工草图不超过 16；建筑/站点对象不超过 200 且仍受实际地图空间限制。新库存容量各 99，完整 schema 拒绝未知资源与越界整数；终局记录采用版本化归档和既有全档维度限额，不静默删回执，也不新建无限增长的第二历史账本

### 只抽小端口，不重写所有版本

1. **库存原语**：泛型 normalize/reserve/consume-part/release/commit，显式传合法资源集合。现有 `inventory.ts` 留六资源 wrapper，旧序列化、排序、取消和终局语义不变；v9 在组合层使用两个 ledger
2. **生产上下文**：注册目录查询、准入、工位等级、入口位置、配方投入/产出账本、终局保存。将这些从现有 `production.ts` / 自动调度里抽为参数；旧 wrapper 仍绑定旧 getRecipe 和点坐标，v9 wrapper 才看研究、入口与额外资源
3. **工作/导航端口**：复用固定四向顺序、移动步长、路径失效、入口令牌和有效工时推进；施工/研究/护理各自拥有状态机与结算。地图查询传有效占地视图，移动和席位释放不能依赖 Phaser 回调
4. **护理原语**：在培养核心增加只返回伤势补丁的纯注册原语，由 v9 World 护理 bridge 校验患者、付款和来源后提交；培养 schema 3 的原有命令不新增可被玩家直接调用的任意设伤接口。v9 完整校验额外验证护理证明，复用培养原有年龄/死亡/风险规则
5. **运行编排**：抽现有 v8 命令/时钟骨架为窄 hooks，仅抽确需复用部分；v8 wrapper 保持原阶段顺序和 admission。v9 新增建筑维护及新工作阶段，所有阶段结束前统一验证候选；禁止复制 simulation-v8 整文件再逐项改类型，禁止把 v9 强转/删字段伪装 v8

共同证明是“原输入不变 → 单个候选 → 全部域校验和容量准入 → 一次发布”。老域源码共享可做无语义变更的端口抽取，旧内容身份、旧保存值及旧回放必须保持。

## 6. 保存、迁移与退出准入

### 显式且可拒绝的迁移

- 首次 v9 仅提供新候选档和明确的 **v8→v9** 迁移。v7 用户先完成已有显式 v7→v8 流程，不加一条未经证明的直通迁移
- 首片只迁移安静经营边界：没有活动远征、待决死亡、突破、教学、待处理指令或活动生产；自动工作已由玩家暂停。条件不足返回定位与正常结束/取消路径，不替用户清空订单
- 旧八点按 legacy-point 一一映射；不改地图、位置、工位、资源、伤势、随机流、历史事实或 ID。新资源余额为 0，研究/新订单为空，不赠药、不补付费研究。新增字段字节与未来义务不足则拒绝
- 旧档原文本和上一代原样保留；新格式先写新一代并回读验证，再切指针。只读恢复档不迁移覆盖，未知版本受保护；v9 损坏不能回退当 v8 解析
- 平台/Session 的混版准入明确拒绝旧版本标签夹带 `sectExpansion` 或 v9 身份；不得依赖旧校验器忽略未知字段，也不得先剥去字段再尝试读取
- 正在运行的旧远征继续在原引擎完成；历史 run 保持原身份。未来允许活动边界迁移是单独工作，不靠伪造终局或修剪历史解锁迁移

### 不能沿用旧证书的理由与最小解法

容量准入应覆盖实测整档 UTF-8 4 MiB、归档行/解码字符/节点、订单/回执上限、所有 ID/版本/日历计数、两本库存和终局记录；当前余额可保存不等于承诺的完工或取消仍可保存。

每个可接受的新任务在开始时保留有限的完工/取消证据空间；两个材料检查点与取消择一分支取真实上界，不把互斥分支相加冒充准确义务。纯草图也必须能取消。维护停用及护理因死亡取消的记录同时进入预算。无解可安全保存时拒绝新增订单，不能删历史或消耗退出保留量。
