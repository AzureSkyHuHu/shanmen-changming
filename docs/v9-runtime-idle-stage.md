# v9 自有空闲批次增量入口

本片只增加内部 `advanceIdleCapacityLimitedTicksV9`。既有严格准入 `advanceCapacityLimitedTicksV9` 保持原样，继续作为差分基准；没有修改 `.3` 的普通记录型入口、codec、Session、界面或部署配置。

## 所有权与来源边界

- 每次外部调用先逐层读取数据描述符，复制成完全隔离的 JSON 树，然后才检查命令。不会先通过描述符检查、再读取可能被命令 Proxy 反射回调替换的调用方属性
- 描述符复制不会执行数据对象的 getter；Proxy 的反射 trap 本身可能有副作用，不能据此声称能检测所有 Proxy 或对调用方数据实现原子快照。复制结果仍须完整验证。世界先复制，命令后复制，后续不再读取调用方世界
- 复制失败直接返回固定暂态错误，不检查可能带 getter/Proxy 的外部异常对象，不把敌意原对象交给严格入口再次读取。有效的严格回退只接收已经隔离的世界和命令
- 初始完整容量查询仍验证全部记录和义务。只有自己的隔离树及以后新建的对象层才递归冻结；外部浅冻结、深冻结或同引用重试都不产生可信凭据
- 没有跨调用 World 缓存、保存的容量证书、调用方证明标志、任意验证回调或新的全局计数缓存。没有复用借用的 archive 页。无推进/无成功命令时保持原输入引用；成功空闲推进返回的深冻结结果与调用方可写数据没有别名

## 唯一增量范围

逐刻确认经营模式且未暂停、没有待执行队列或远征、没有任何活动的旧生产/施工/宗门生产/研究/护理所有者，也没有计划蓝图、闭关、授课、活动锁或未决死亡。尚未发生月份/生日变化、自动计划未到期、维护未到期，人员位置和 traveling 不会发生纠正。活动成长义务明确排除；原有不变的有限寿尽义务继续保留。

此时正常准备的完整 JSON 内容只变化五个非负安全整数：simulationTick、calendarTick、施工 revision、宗门生产 revision、研究 revision。三者空闲阶段仍各增加一次修订，护理和修炼修订不变。沿用冻结子树，只创建并冻结根、clock、sectExpansion 及三个领域的新对象层。

整封包 UTF-8 增量是这五个 JSON 数字新旧宽度的精确差值。9→10、99→100 各增加5字节；整数值在安全范围内，不用浮点对数估算。其他字符串、行数、解码节点数、构筑/修炼 reader 当前字符数和世界内容不变。

原有 progression 与 sect 的共享计数宽度保留量可能随数字增长缩小。本入口保守沿用旧保留量，不将减少当成释放。当前五个数值和整封包字节逐刻递增，并以减法核对每一维的安全整数上限，避免相加舍入。该向量有独立私有类型，不能冒充完整 `ManagementCapacityV9`。

## 严格回退

任意命令、活动所有者、计划蓝图、月份/生日/生命周期边界、维护/计划到期、时钟记录已满、接近 MAX_SAFE_INTEGER 或保守预算无法证明时，整个剩余批次交给未改变的严格入口。严格入口重新完整查询当前来源，然后执行原有正常候选和无可选增长恢复顺序。

隔离世界上先执行只用于排除的轻量探测；明确活动/到期/未知形状，以及探测遇到缺失字段的情况直接交严格入口，不额外先做一次完整容量查询。通过探测不授予任何准入权，尝试快路仍必须完成全量来源及容量查询。活动工作、规划、维护等初始回退的完整查询次数与原严格调用逐项比较。

特别是，保守沿用向量绝不参与不足维度非增比较或终止释放认证。数字变宽导致保守上界碰限时也先重算，不能因为较粗上界而假停，更不能把它当作释放前态夸大可释放空间。所有命令排序、精确重试、拒绝顺序和停止详情留给原严格实现。

## 证据与性能范围

新增差分测试覆盖普通/256条真实命令历史、20刻一次完整查询、五数位增长、命令/重试/暂停、月结/生日/寿尽、规划/维护、五类实际工作所有者、真实闭关决定、保守数字增长回退、未来不足、近整数上限和完整时钟表。敌意用例覆盖 getter、描述符、稀疏数组、冻结借用、源调用后突变及 commands Proxy 的重入修改。时钟满表使用真实死亡归档后的明确有界历史压力夹具，不冒称模拟了全部年份。

`tools/benchmark-v9-runtime.ts` 在保留原 record-only/strict 调用之外增加 owned-idle 模式，记录完整查询和精确标量查询次数，每个优化测量结果在计时之外与严格结果比较。无墙钟耗时单元断言。

实现阶段未由作者运行测试、类型检查、构建或基准；统一集成负责人串行执行并记录实测终态。既有基线见 `v9-runtime-capacity-stage.md`。不能把本片文件存在当作验证通过，也不能据空闲批次成绩声称重历史单次外部调用、活动工作、1倍速50毫秒或3倍速已解决。

若后续测量显示每次外部认证仍是主要瓶颈，可另审一个不可伪造、私有持有深冻结世界的运行实例：外部输入仅在创建/替换时完整验证，命令和每个发布边界仍保持现有准入，退出时只给隔离快照。该设计需要独立的生命周期、替换/失效、异常后恢复和应用接入证据；本片没有实现可复用实例或会话。一次遍历同时计字节/UTF-16字符/节点的共享计量器亦留待独立测量与审查，不在本片改写公共 helper。

## 2026-10-02 实测与限制

最终40项定向差分/敌意输入测试通过19.50秒，双类型检查通过。随后串行20样本基准在每次调用核对原入口、严格入口和空闲入口的实际结果一致，夹具准备不计入耗时。

同次测量的 p50 / p95（毫秒）：

- 新世界20刻：严格185.88 / 201.87；空闲优化10.07 / 12.05
- 256条真实历史20刻：严格761.70 / 895.79；空闲优化40.29 / 44.70
- 256条真实历史单刻：严格78.61 / 85.68；空闲优化42.60 / 52.64
- 三人混合工作单刻：严格42.71 / 49.07；优化入口回退44.61 / 48.46

合格空闲20刻仅1次完整查询+20次精确标量处理。初版遇到工作/月结先多做1次查询而退化，最终通过只会拒绝快路、不会赋予准入的独占副本预检查移除冗余；回退单刻保持严格入口的2次完整查询。

这证实空闲批次有显著改善，不能宣称性能问题已全部解决。长历史冷启动单刻p95仍超过50毫秒，活动工作没有启用快路，渲染、3倍速、36弟子、长期年代和移动端仍未验收。下一步独立评估重复字节/字符/节点计量开销，不扩大快路权限以凑性能。
