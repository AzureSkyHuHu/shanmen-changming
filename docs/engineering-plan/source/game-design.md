# 山门长明

单人修仙宗门浏览器游戏设计方案与项目架构

暂定游戏名  山门长明    规划版本  0.1    日期  2026年10月1日

<a id="s01"></a>
## 01  产品方向与已确认边界

推荐把游戏做成可长线经营的俯视角宗门模拟。玩家持续主持宗门，安排弟子的修行、生产和出征，看见他们在山门中生活，也承担突破失败、伤病、衰老与传承的后果。经营为修行提供条件，修行为探索解锁能力，探索带回新资源与矛盾，最终形成几代弟子共同建设的宗门。

| 已确认要求 | 本方案的落实方式 |
| --- | --- |
| 单人浏览器游戏 | 单机存档和离线可用资源优先；1.0 不依赖账号、联机或付费服务 |
| 中国修仙与可见宗门 | 俯视角山门、弟子移动、生产和练功行为；场景可直接点选人物和建筑 |
| 自动战斗加关键指令 | 自动普攻与技能规则；玩家可暂停、集火、移位、开阵、保命和撤退 |
| 寿命与突破风险 | 年龄、寿元、闭关成本、失败后果和死亡；决定前提供可理解的风险预告 |
| 肉鸽构筑与可扩展战斗 | 角色永久天赋树、技能与配装、局内三选一；统一技能、天赋、状态和效果的数据合同 |
| 首发中英双语 | 默认简体中文，可切换英文；所有玩家可见文本有稳定键，英文缺项逐键回退中文 |
| 先完整策划和项目架构 | 本阶段只交付设计与技术方案；所有功能、数量和性能指标均为待实现目标 |

### 推荐决策与核心体验

建议采用中国山水淡彩的 2D 俯视场景、持续但可暂停的经营时间、分批入门的弟子群体，以及有终章也能继续经营的战役。下文所有内容数量、概率、产量、寿元、节奏和性能预算都是首轮设计基线，未经实现或平衡测试；它们不构成既成效果或工期承诺。

短循环：发现瓶颈 → 调岗或建设 → 看见行为变化 → 收到产出与关系反馈

中循环：培养小队 → 准备丹药法器 → 出征并判断风险 → 带回资源和新配方

长循环：招收与传授 → 突破与立派 → 师徒更替 → 抵御终章灾劫 → 留下宗门史

阅读路径：第 2—17 节定义玩法、构筑与范围；第 18 节定义交互与美术；第 19—25 节定义工程、战斗扩展和验收；第 26—27 节给出实施顺序、风险、素材与来源。

计划分四层维护：总体规划回答做什么与做到哪里；专项计划分别管理经营、成长构筑、战斗、美术和工程；详细计划定义数据、公式、交互和验收；执行计划拆成有依赖、有完成条件的任务。任务须追溯到本方案章节与对应测试，不能只按“工作了多久”判定完成。

## 02  可玩版本范围与通关目标

完整 1.0 的目标是一条能完成、能失败、能恢复、能跨代延续的宗门战役。垂直切片用于验证同一套系统能否联动，不能把只会产资源的地图加几张面板视为完整版本。

| 内容项 | 垂直切片 | 完整 1.0 建议基线 |
| --- | --- | --- |
| 场景与进度 | 1 张山门地图，1 个探索区，练气至筑基 | 1 张可扩建山门；3 个探索区；练气、筑基、金丹、元婴 |
| 弟子与建筑 | 6 名有差异的弟子；6 类建筑 | 开局 4 人，中期 12—16 人，常规 24 人，硬上限 36 人；14 类建筑，每类最多 3 级 |
| 功法与敌人 | 2 条流派；8 个技能；4 类普通敌人；1 个首领 | 剑体丹符 4 门类；24 项技能；18 类普通敌人；6 类精英；3 个区域首领 |
| 天赋与构筑 | 2 棵天赋树原型；12 张局内机缘；2 套可用构筑 | 4 棵各 9 节点天赋树；12—18 个角色特质；48 张局内机缘；4 套核心构筑 |
| 配方与事件 | 8 个配方；12 个事件模板 | 36 个配方，含丹药、法器、阵材；48 个事件模板；12 个主线节点 |
| 经营与传承 | 食物、建设、修炼、关系、突破、存读档闭环 | 季节生态、师徒、伤病、寿元、遗产、宗门名望与终章 |
| 完成条件 | 能从入门玩到首领与筑基，保存后继续 | 三处封印重建；宗门承受终章灾劫；结算传承，可继续沙盒 |

### 战役结构与失败恢复

第一章立足：保证生计并建成授业体系。第二章立派：在三种资源短板中选择主修方向，完成筑基小队与第一处封印。第三章传承：培养接班人，处理旧友衰老和区域势力的长期后果。终章护山：通过阵法、物资与战术共同抵御灾劫，战力不能替代全部经营准备。

个体死亡保留在宗门史中。掌门或长老也是世界中的人物，但玩家代表延续的宗门治理，不绑定一个必然寿尽的主角；新掌门任命保留建筑、典籍、关系记忆和大部分库存。

全员覆灭不静默删档：展示缘由、损失与复兴条件，可从最近安全存档恢复；标准模式可用宗门遗产招回一批流民重建。硬核模式须在开局明确选择，不能在中途暗改规则。

### 明确不进入 1 0 的内容

不做多人、市场交易、实时 PvP、开放世界无缝漫游、无限地图生成、全角色自由动作连招、复杂家族生育、付费抽卡和自动云存档。内容扩展应复用已验证的模块，不以增加名词掩盖循环薄弱。

<a id="s03"></a>
## 03  时间节奏与开局体验

推荐经营历法在 1× 下每 60 秒推进 1 个游戏月，12 个月为 1 年。1× 的 100 年约为 20 小时，只是量纲换算，不能据此承诺通关时长；暂停、战斗、阅读、3× 和安全快进都会改变实际游玩时间。首轮测试以 100—150 年能完成主要传承与终章为观察窗口，之后按体验调整。

### 三种时钟各自负责什么

| 时钟 | 负责内容 | 一致性规则 |
| --- | --- | --- |
| 经营时钟 | 年月、年龄、生产、建造、研究、需求和日程 | 固定步长更新；同一份权威状态只结算一次；暂停时全部停止 |
| 表现时钟 | 步行动画、风、云、呼吸、界面过渡 | 平滑插值和装饰；绝不直接创造资源、经验或寿命变化 |
| 战斗时钟 | 攻击、弹道、冷却、状态、首领阶段 | 进入战斗冻结经营历法；战斗后按明确的任务规则结算远征耗时 |

远征按路线节点结算战略耗时：旅行节点推进标注的月份，普通战斗节点冻结历法，返程节点再推进标注月份；每个节点用唯一结算标记只提交一次。出发预告整趟预计月份并预留口粮，队员离岗期间不生产。节点推进仍经过同一安全检查与资源逻辑；不额外把战斗现实秒数换成年龄，也不在回程再扣整趟时间。

### 暂停与安全快进

默认提供暂停、1×、3×；标签页隐藏、窗口失焦进入安全状态时暂停，回来先展示发生到哪里

闭关决策、重大事件、濒死、短粮、建筑阻塞和首领战前停止快进；致死结果必须在前台可见地确认/播放

快进到下一检查点时仍调用相同的生产、需求、损耗和风险逻辑，不直接把“目标年份”赋值给世界

不做自动离线衰老。以后若加离线收益，须独立开关、上限和安全结算，不推断离线期间发生死亡

### 开局顺序与混合年龄层

开局安排 1 名已有伤势的年长传功师、1 名成年骨干、2 名年轻弟子，共 4 人。老者的寿元与经历让第一代传承自然出现；新人不会仅因玩了两次就集体寿尽。年龄初值通过种子生成，并确保至少两名能承担生计。早期招募至 6—8 人后才形成 4 人远征与留守分工，中期 12—16 人，常规目标 24 人，硬上限 36 人。

前 10 分钟的教学目标是看到一次完整生产、一次共同进餐、一次修炼反馈和一次出征准备。首小时观察目标为一次低风险远征、一个关系事件和一次可选择的筑基准备，不强制在固定分钟突破。关键说明随真实情境出现，玩家可回看。

<a id="s04"></a>
## 04  宗门场景与可见工作模拟

山门是一张有道路、坡地、溪流和灵脉的可扩建地图。初始只开放小片可建设区域，通过勘探和主线解锁地块。建筑外观、人员路径、生产装置和灵气流向共同说明宗门正在做什么，资源不应只在面板里上涨。

### 角色行为与岗位分配

弟子按“生理安全 → 受伤照护 → 已承诺任务 → 日程 → 兴趣/社交”的优先级选择行为。每个行为包含目的地、占用岗位、预计耗时、输入预留、完成产出与中断规则；界面显示当下行为和为什么这样做。

| 行为 | 场景表现 | 状态和经济影响 |
| --- | --- | --- |
| 耕作与采集 | 前往地块，工具动作，成熟/枯萎状态 | 按有效工时产出；季节影响产率；采空后恢复或轮作 |
| 炼丹与锻造 | 领取材料，进入工位，火焰与进度 | 开工先预留输入；完成一次才产出；中断按规则退还未耗材料 |
| 修炼与授业 | 进入洞府或演武场，打坐/演练/围听 | 灵气、心境、师承共同决定效率；授业占用师父时间 |
| 休息与交流 | 回居所、用餐、探望、同行 | 恢复疲劳；关系按事件变化；避免每秒随机刷关系 |
| 救援与防灾 | 搀扶伤员、运水、修补阵基 | 抢占非紧急岗位；消耗医药/材料；明确暂停原因 |

### 空间应产生选择

灵田靠水获得稳定产率，丹房与仓库相邻减少物流，洞府靠近灵脉提高修炼，却与吵闹锻炉冲突。距离以可达路径计入运送耗时；不模拟每一根木材实体，避免物流成为纯点击负担。道路可增加运力并让交通更易读。

岗位使用优先级和配额：食物至少保留 2 人、伤者免战、突破候选闭关、炼丹订单优先等都可批量设置。玩家能临时指派，但系统必须说明规则冲突。任务没有可达目标、原料不足或工位被占时进入可诊断状态。

### 拥堵与中断约束

寻路按任务变化或阻塞触发，不给全体角色每帧重算。建筑前预留入口与排队点，多个岗位使用席位令牌；挪动建筑前校验入口与道路。被打断任务写入唯一任务 ID，恢复后不得重复消耗或产出。停在原地超过阈值时给出“道路不通”，允许取消并安全返还未使用投入。

场景验收要求：无需打开全局资源表，玩家能认出主要生产区、当前建设、修炼地点、伤员与危险预警；点击任何忙碌人物能追到其任务、耗时和产出的来源。

<a id="s05"></a>
## 05  弟子身份需求关系与传承

弟子的价值来自适配和经历。每人具有姓名、年龄、出身、性格、根骨取向、兴趣、伤病、所学、师承、关系和记忆。灵根采用倾向组合，例如木火相生利炼丹、金水偏剑诀；不设一个覆盖所有价值的 SSS 总分，也不让某一血统在全部系统中占优。

| 层次 | 首版数据与规则 | 对玩家的实际选择 |
| --- | --- | --- |
| 资质 | 五行偏向与悟性/体魄/心性分别记录 | 修炼、职业、技能和心魔应对各有所长 |
| 需求 | 精力、温饱、心境、归属感；都用少量可读档位 | 长期超负荷会降效或受伤，短期调度有代价但可恢复 |
| 性格 | 2 个正负并存特质，如执着、谨慎、好胜、念旧 | 执着能加闭关耐性，也可能拒绝休息；不存在纯免费增益 |
| 关系 | 信任、亲近、芥蒂三个轴；师徒关系单独记录 | 组队、授业、照护触发变化，矛盾不会由无理由骰子决定 |
| 记忆 | 保存关键事件标签、关联人物和时间 | 相救、背弃、突破、离别影响后续选择与宗门史 |
| 传承 | 功法熟练、心得、弟子、纪念与遗物 | 老者可转为传功岗位，把时间用于培养接班人 |

### 关系如何进入系统

师徒连续共同授业积累信任，配合小队获得协同条件。争夺同一稀缺洞府可能产生芥蒂，但玩家可轮换、调解或补偿。每个重要关系变化附“因何发生”，并限制单个周期的变化量，避免礼物无限堆到满值。浪漫关系不是 1.0 的必要系统。

心境低落先影响效率和接受任务的倾向，不直接生成无法预测的猝死；低落原因可以追查、缓解。性格可以随重大事件形成新倾向，但保留人物连续性。离宗应经过明确冲突和预告，给玩家可行动的窗口。

### 死亡后仍留下什么

确认寿尽或阵亡后，记录人物生平、师友、最重要事迹和遗愿；遗物与典籍按已建立的传承关系交接。传功需要生前投入，不能把全部熟练度在死后无损复制。墓碑或纪念堂可供拜访，师徒记忆影响下一代的志向和事件。

推荐损失顺序为：伤势与任务受阻 → 资源或机缘损失 → 不可逆的重大后果。玩家在充分告知后仍可冒险。平常生产、离线或镜头外日常，不随机结算不可预见死亡。

<a id="s06"></a>
## 06  修炼境界寿元与突破风险

修炼由修为、功法理解、身体状态和突破材料共同推进。境界决定可承受的法器、功法和区域风险；熟练度决定同境界的具体表现。生活职业与战斗培养共享时间，使“把最强弟子长期留在丹房”成为有价值的决策。

| 阶段 | 建议寿元上限 | 解锁与限制 | 主要瓶颈 |
| --- | --- | --- | --- |
| 凡俗入门 | 80 年 | 基本劳作、基础养气；能通过教学入道 | 生计、启蒙与适合功法 |
| 练气 | 110 年 | 基础术法、低阶法器、近山探索 | 灵气供给、功法适配 |
| 筑基 | 180 年 | 稳定职业专精、强化技能分支、护山阵 | 筑基药引、身体与心境准备 |
| 金丹 | 360 年 | 流派核心、授业强化、区域首领 | 丹成品质选择、功法理解、稀缺阵材 |
| 元婴 | 600 年 | 终章担当、宗门级能力、传承加成 | 有限机缘和多项准备；不无限延长战役 |

以上寿元是基准上限而非保证存活年份。突破成功可提升上限；伤势或禁术可留下寿元代价，必须事前明示。年龄继续按同一经营历法增长。境界不会把年龄重置，也不叠加重复的延寿奖励。

### 透明的突破界面

展示目前成功率区间、各项加减因素、需要占用的闭关月份、丹药/阵法消耗，以及失败可能导致的修为倒退、伤势或死亡。普通准备齐全的突破优先产生可恢复失败；致死风险主要来自高阶劫难、重伤强行突破或明确选择的冒险方法。

p = clamp(0.05, 0.95, 0.45 + 0.20U + 0.15F + 0.15M + 0.10A - 0.25I - 0.20K)

示例公式中 U 为功法理解、F 为根基准备、M 为心境、A 为阵法助力、I 为伤势、K 为该次劫难压力，均归一到 0—1；系数只用于原型试验。成功率与“失败后死亡率”必须分别显示，不能把 70% 成功偷换成 30% 必死。

### 失败不是同一件事重复点按钮

失败产生可诊断的原因和修复路径，例如经脉受损需要休养，根基不足需要历练，功法不合可调整路线。加入同阶段的准备收益递减和可选择机缘，避免无限刷药直到 100%。随机种子、风险抽样和结果提交在存档中成对记录，读档不能因刷新页面无意重复扣材料。

首轮平衡重点：普通弟子能通过合适岗位与师承成长；高资质仍需付出时间；长寿者占据资源时仍有培养后辈的收益；玩家能主动选择何时承担不可逆风险。

<a id="s07"></a>
## 07  资源经济与防止卡死

经济围绕生产、维护、培养和探索构成闭环。每种资源都应有至少一个持续用途，并尽量提供两个获取路径；稀缺资源负责路线选择，基础资源不能因一次损失永久锁死战役。库存、预留、在途和已消耗必须分开显示。

| 资源 | 来源 | 主要消耗与回收 |
| --- | --- | --- |
| 口粮 | 灵田、采集、低效率购买 | 人口维持、远征补给；损坏/过期作为温和库存压力 |
| 木石与矿材 | 采集、采矿、拆除返还 | 建造、维护、锻造；扩建和道路形成持续投入 |
| 灵石 | 任务、交易、特殊采集 | 采购、功法研究、阵法维护；交易差价防套利 |
| 药材与丹药 | 药圃、探索、炼丹 | 恢复、闭关准备、疗伤；按配方加工，不凭时间自动升级 |
| 灵气 | 灵脉、聚灵设施、季节变化 | 修炼与阵法的每月共享预算；不是可无限囤积的通货 |
| 稀有机缘与心得 | 首领、事件、授业、区域探索 | 突破、流派研究和高阶装备；关键任务有保底或替代路线 |

### 生产和消耗的可解释计算

output = baseRate × activeTime × skillFactor × facilityFactor × seasonFactor × supplyFactor

activeTime 只计入已获工位、材料齐备且可工作的权威时间；疲劳、缺料、路程影响有效工时。生产完成采用事务提交：校验已预留输入 → 扣除投入 → 增加产出 → 写入任务完成标记。不得按动画完成次数发资源。

首轮食物基线可设为每人每月消耗 1 份，一名普通农作弟子在稳定季节产出约 5—6 份，支持开局 4 人；扩至 6—8 人时增加第二名农作岗位。受伤、建设、闭关和远征挤占劳力后会显现压力；所有人数阶段都要通过经济模拟验证，不能仅凭这组示意数字锁定。

### 耗散与反套利

建筑按等级增加维护，丹药高阶材料难替代，阵法长期占用灵气，出征消耗补给。拆除返还低于原成本，买卖有价差且按同一结算口径，配方循环必须无法净增原料或灵石。库存上限只应制造仓储选择，不导致无提示的关键物品销毁。

### 保底与救济边界

短粮先预警并允许停工觅食；低收益采集点始终可用，不能需要粮食才能取得第一份粮食

首个突破材料有一条确定获取路线；首领失败可疗伤再战，关键任务物不会永久遗失

交易救济价格较高且有冷却；不提供可循环套现的无代价赠送

关键建筑可拆改并返还部分基础材料；提供库存与流水追踪，让玩家找到亏损原因

## 08  建筑研究与经营路线

建筑是行为发生地，也决定土地、岗位和灵气如何分配。1.0 建议 14 类功能建筑，每类最多 3 级；升级改变容量或功能，不能只把所有数值乘二。外观至少能区分施工、可用、缺料和损坏状态。

| 建筑组 | 包含类别 | 主要选择 |
| --- | --- | --- |
| 生计与物流 | 居所、膳堂、灵田、仓库 | 人口容量、食物稳定、运送距离与库存余量 |
| 生产与照护 | 药圃、丹房、锻造坊、医舍 | 培养资源与恢复能力；人手在生产和出征之间竞争 |
| 修行与传承 | 洞府、演武场、藏经阁、传功堂 | 独修效率、队伍训练、研究路线与师承容量 |
| 宗门与防卫 | 议事堂、护山阵枢 | 政策、招募、出征组织、灾劫防御 |

### 建设订单与研究订单

建设前显示占地、入口、地形限制、一次性材料、所需有效工时与完工后的每月维护。可先画蓝图，材料不足不直接清空仓库；开始施工后锁定该订单预算。取消时按已经实际消耗的比例返还，挪动成品建筑需要搬迁工时。

研究分为生产、修行、阵法和传承四条线，共建议 16 个节点。每个节点要有可玩变化，如新工位、替代配方、技能组合或风险控制；避免只堆无感的 2% 加成。研究消耗心得、灵石和研究岗位工时，玩家只能同时集中推进有限项目。

### 三种可行经营风格

丹修立宗：药圃与丹房强，突破和疗伤稳定；金属和护山能力偏弱，依靠采购或针对性探索补足

剑修立宗：出征快、单点作战强；消耗较多法器维护和伤药，练功挤占生产，需要师承和补给支持

符阵立宗：防卫、灵气分配和控制强；固定建设投入高，远征需携带有限阵材，不能把宗门阵法完整搬走

任何路线都保留基础农作、疗伤和探索能力。专精改变达到目标的成本与顺序，不把唯一关键材料锁在玩家没有选的不可逆支线里。路线可通过改造和转授逐步调整，成本明确且可负担。

### 日常管理不应变成重复劳动

允许设置库存上下限、长期订单、岗位最低人数、伤员自动休养、弟子日程模板和出征补给模板。自动化每次只执行已定义的低风险规则；突破、消耗唯一遗物、重大交易或高风险出征仍需要玩家做决定。所有自动化提供可读日志和一键暂停。

<a id="s09"></a>
## 09  自动战斗与关键战术指令

战斗使用俯视 2D 小队制，前期 4 人、后期最多 6 人。每人携带 1 个普攻、2 个主动术法、1 个被动技能，另有武器、法衣、法器 3 个装备槽。默认由行为规则自动选敌和施法，玩家在关键时刻干预；战斗深度主要来自站位、目标、冷却、配装和局内构筑，不来自不断点击普攻。

| 控制 | 默认行为 | 玩家介入与限制 |
| --- | --- | --- |
| 集火与护卫 | 优先攻击可达且威胁高的目标 | 标记目标或保护脆弱同伴；可取消，目标失效自动解除 |
| 移动与阵型 | 保持流派合适距离，避开已知危险区 | 选中/框选移动；三种阵型；暂停时排指令 |
| 关键术法 | 按条件自动释放常规技能 | 可关闭指定技能自动施放，把净化、护盾、打断留给危险阶段 |
| 阵法与丹药 | 不自动消耗稀缺救命品 | 共享阵材/指令额度和冷却；避免无限暂停灌药 |
| 撤退 | 不自行冒进追击到地图边缘 | 撤退有明确出口与读条；成功保人但损失未带走战利品 |

### 四条战斗流派

剑修擅长单点突破和打断，体修承受压力并保护队友，丹修提供持续伤害、治疗和转化，符修提供范围术法与阵纹控制。治疗由有限回复、护盾、净化和战前准备共同承担，避免必须携带某个指定角色才能出门。每门类配置 4 个主动与 2 个被动技能，共 24 项；丹修与符修同样必须能独立启动自身的基本循环。

### 可解释的数值顺序

战斗以第 21 节的统一流水线为唯一规则来源，防御结算先于护盾扣除，濒死保命先于死亡提交，结算后触发只进入后续队列。所有伤害带来源角色、技能与事件 ID；同种子、状态和指令的复现性必须实际测试。

damage = max(1, rawDamage × elementFactor × 100 / (100 + defense))

这只是早期伤害曲线示例。防御使用递减收益避免高护甲直接无敌；暴击、控制抗性与减伤设置上限。敌我同类效果遵循同一叠加规则，界面明确刷新、相加或互斥。

### 受伤倒地与死亡

生命归零进入倒地而非立即删除人物；队友可救援，重伤者不能继续无代价输出。危险首领或特定攻击可造成致命后果，但战前须标记。战败结算应列出“谁受伤、谁撤离、什么丢失、为何死亡”，并写入宗门历史。无人在场观看时默认暂停战斗与致死结算。

验收重点是玩家能回答：刚才为什么受伤、下一次能改变什么，以及自动战斗在没有命令时是否仍可完成低风险任务。

技能分类使用多轴标签，同一个技能可以同时是剑系、主动、远程、穿透、物理与打断。界面按门类和用途浏览，规则按标签查询，避免日后新增一条天赋就加入针对技能名字的特判。下列 24 项为首发候选完整名称与功能目录，数值、资源映射和 schema 尚待制作与测试。

### 解锁与装配规则

基础教学先给两名战斗弟子的启动技能，首条标准远征前具备 2 主动和 1 被动槽。宗门逐步开放丹、符与装备制作，前 6—8 次远征作为交齐关键构筑工具的观察目标。终极技能需门类研究与角色境界条件，替换一个主动槽，具有长冷却/额外资源成本，不能额外无限加槽。

首轮技能预算可按常规主动 8—20 灵力、4—10 秒冷却，保命/强控制 15—30 灵力、12—20 秒冷却，终极 50—80 灵力、35—60 秒冷却起测。每项技能的精确成本、前摇和系数在详细配置任务中逐项登记，不能把区间当成已完成的可运行数据。

召唤首版只做每施法者至多 1 个、持续时间明确的纸傀，不培养、装备或继承，也不拥有完整弟子 AI；如果基础 Summon 操作尚未通过测试，纸傀保持内容阻塞状态，不用临时脚本绕开执行器。48 张机缘已有数量分类和核心示例，完整命名及逐卡配置仍是制作待办，不能当成已完成数据资产。

## 11  四层成长与永久天赋树

肉鸽构筑是核心玩法。宗门解锁、弟子终身成长、出发配装和局内机缘分别保存、分别结算：前两者建立长期身份，配装保证基本可玩，局内三选一改变这一趟远征的组合与打法。当前设计假设为“一次远征是一局”，可包含多场战斗；如果改成单场即一局，需整体重配抽选节奏与奖励。

| 层次 | 保留范围 | 首轮设计基线 |
| --- | --- | --- |
| 宗门传承 | 跨远征与弟子世代 | 解锁功法、制作与机缘池；主要拓宽选择，不无限叠加全体攻击力 |
| 弟子成长 | 该弟子生命周期 | 1 个先天天赋，最多 1 个经历天赋；主功法 3 分支、每支 3 节点，总计 9 节点，最多获得 5 点 |
| 出征配装 | 已学技能和装备长期保留；远征内锁定 | 普攻、2 主动、1 被动；武器/法衣/法器 3 槽；宗门内可免费调整技能与已获天赋点 |
| 局内机缘 | 仅当前 runId 的远征 | 标准路线 6 次三选一，深层最多 8 次；短教学路线 2—3 次；首领前形成组合 |

### 树要允许取舍

四棵天赋树对应剑、体、丹、符，每棵 9 个节点。分支终点要求本分支前两点，终身最多 5 点，因此不能同时取两条分支终点；前置和互斥由核心验证，不由按钮是否变亮决定。先开放少量节点教学，再逐步给足配装槽位，第一条标准远征前必须已有能自行启动的基础组合。

节点应改变作用方式，例如延长剑痕窗口、把部分治疗转为护盾、交换控制范围与伤害，而不全是加攻击。推荐初版 12—18 个角色长期特质、18 件装备基底和 12 类受限词缀。根骨影响适配成本，不能让某一出身独占全部强节点。

### 永久与死亡的准确含义

永久天赋在离开战斗、结束远征和读档后仍生效，直到该角色死亡或规则明确改变。它不意味着把死者全部战力复制给接班人。已经向宗门传授的功法、心得和纪念可继承；角色天赋、未传授熟练与个人经历按传承规则处理。

### 强度预算

同境界中，装备与永久天赋的常规静态提升合计先以约 35% 为观察上限，更多收益用变体和条件换取。完整局内构筑的持续输出先观察是否落在出发底盘的 1.6—2.2 倍区间；这是平衡目标，不能据此声称四套构筑已平衡。普通战斗不得要求抽到指定稀有卡。

同类增伤进同一加法桶；暴击、急速、减伤、吸血、护盾和控制分别设置上限或递减。先测试暴击率 50%、暴击倍率 2 倍、额外急速 40%、持续减伤 60% 的护栏，再结合敌人节奏调整。

每个门类有 3 条分支，每支按一阶、二阶、终点顺序连接，共 36 个节点。每位弟子只修一棵主树，最多 5 点，每节点 1 点；两条终点至少需 6 点，因此不可兼得。以下为节点名称、作用方向与构筑联系，正式系数和条件通过统一数据协议制作。

### 点数获取与重新配置

建议入道获得第 1 点，完成练气授业/历练目标获得第 2 点，筑基、金丹、元婴各获得 1 点，共 5 点。点数由明确的个人里程碑获得，不能反复洗境界或重复任务刷点。宗门内可免费重分已获点数，按依赖逆序撤销节点；出征后锁定，直到远征结束。

先天天赋、经历天赋、技能栏被动与树节点是不同来源：它们可表达不同身份，但同类数值仍进入统一修正桶，不能因为出现在四个面板就各自加一层最终乘区。更换主树需满足已学功法条件并在宗门内执行，不能绕过技能学习。

### 节点设计与实现验收

叶节点应能说明它改善哪条循环，以及付出什么机会成本。需要剑痕、护盾、毒或纸傀的节点，解锁时必须已有相应技能或节点自身提供启动能力。共炉、回响、三曜与剑阵分别呼应四套主构筑，但局内核心缺席时也不能让整棵树失去基础价值。

校验每棵图无循环、终点可达、5 点无法双终点、重分不残留旧来源、存读档点数不重复发放。师父死亡不重置弟子已经合法获得的点数；新弟子不能自动继承死者整棵树。

<a id="s13"></a>
## 13  局内三选一与远征结算

建议首版 48 张局内机缘，作用域分为 36 张个人、12 张全队；功能分类覆盖 12 张通用、24 张门类、8 张跨门类、4 张路线主题。作用域和分类是两套统计维度，不能相加成 96 张。机缘默认只影响战斗，不增加宗门产量、寿命或突破率。

### 选什么给谁以及何时失效

个人机缘先选卡，再从卡面列出的适配弟子中选持有人，持续本次远征。持有人阵亡后失效，不自动转给别人。全队机缘绑定 runId，只影响符合条件的在队成员；同名光环按规则只取最高值，不能因为 6 人在场就把同一个增益乘 6 次。

卡面必须显示作用对象、生效范围、触发条件、数值、层数、冷却和当前联动。中毒、护盾、剑痕、战斗冷却等单场状态按定义清理，局内机缘跨战斗保留。伤势、耗寿、消耗品、耐久与死亡另行结算；关闭浏览器保存当前远征，不自动视为撤退或重抽。

### 抽选流程与保底

先过滤：排除已满级、互斥、前置不足、无人适配和缺少触发来源的卡；需要毒/盾/剑痕的卡必须已有来源，或自己提供来源

再加权：基础权重结合队伍标签、短板和近期出现情况；每组含当前方向、通用生存/资源、桥接探索三种选择，三张不重复

最后保底：前两次标准选择至少出现一次能立即工作的核心；拿到核心后，两次标准奖励内至少出现一次可用补件，但不保证指定终极组合

候选不足时补通用卡；每局 2 次刷新，至少出现 1 个此前未展示的合法选项；允许放弃卡换本次补给，不能用存读档免费刷新

出发可选 2 个偏好标签，只影响倾向。权重倍率设上下限，新内容不能挤掉通用选择。若合法池无法提供至少一个新选项，则禁用刷新并解释原因，不消耗刷新次数；极端空池直接给补给退路。生成的 offerId、三张 ID、候选持有人和随机流立即保存；选择、奖励次数与机缘一起提交。预览不消耗正式奖励随机流。

规则冲突时按合法性与存活适配 → 可用通用退路 → 核心/补件保底 → 三种方向分配 → 权重偏好处理，不能为了凑三种方向而发出无效卡；内容不足触发诊断并使用退路。

### 结束远征只有一个结算入口

安全节点撤回保留已获得战利品；战斗中紧急撤离须完成撤退过程，已封存物保留，未封存物首轮可设保留 50%；全灭时未封存物清零。比例待测试，但提示与实际必须一致。通关、撤回和全灭统一调用结束入口，清除 run/encounter 来源，保留合法 character 来源与宗门资产。终点奖励给可带回物资与解锁，不再给马上失效的机缘。

## 14  构筑示例 回潮剑阵与药火共炉

四套示例都由出发配装提供启动器，局内机缘提供效率、变体与队友协作。标准队伍前期 4 人、后期 6 人，下述 2—3 人是核心配合，其余席位可补输出、生存或控制；不得将示例中的核心人数误作队伍上限。

### 回潮剑阵

底盘由剑修的留痕剑稳定施加剑痕，归锋消耗最多 3 层剑痕强化一次攻击，体修负责护盾。永久分支可延长剑痕窗口，装备补基础属性或目标变化。即使没有抽到组合卡，剑修也能自己上痕再消耗。

| 机缘 | 效果 | 防循环约束 |
| --- | --- | --- |
| 息归剑脉  个人 | 一次消耗 3 层剑痕后返还固定灵力 | 每 3 秒最多一次；只响应真实消耗事件 |
| 守中生锋  全队 | 护盾实际吸收敌方伤害后，为集火目标加 1 层剑痕 | 共享每 3 秒一次；自伤和空盾不触发；不按队员数量复制 |
| 错锋  个人 | 消耗剑痕后，下一次普攻附加一段低系数剑气 | 剑气带 proc 标签，不触发同类追加攻击 |

可见循环是护阵承伤 → 生成剑痕 → 集火归锋 → 返还灵力。长单体战表现较好；频繁换目标、清除剑痕或隔绝前后排的敌人迫使玩家改变节奏。玩家干预点是集火、留住归锋与护盾时机，而非不断点击普通攻击。

### 药火共炉

丹修用青雾施毒，符修的焚瘴消耗最多 3 层毒，转成按符修属性计算的额外火伤。层数决定系数，不重复把原毒伤、暴击和增伤再次乘入。配套治疗只在真实施法与资源支付后生效。

| 机缘 | 效果 | 防循环约束 |
| --- | --- | --- |
| 温药余性  个人 | 毒被队友主动技能消耗时，施毒者得 1 层药华；下一次治疗消耗强化 | 最多 2 层；追加伤害不算主动技能 |
| 药烟延绵  个人 | 引爆后仍活着的目标保留 1 层新毒 | 每目标 4 秒一次；新毒不追溯触发本次消耗 |
| 余火照炉  全队 | 完成引爆后给生命最低队友小额护盾 | 按根行动限次；同分按稳定角色 ID 选人 |

循环是上毒 → 择时引爆 → 积药华 → 治疗与护盾。群敌和持久战较有优势，净化与高压短战更难。若队友阵亡，失去的协同在卡面解释，后续抽选提供能让幸存者继续工作的方向。

## 15  构筑示例 玄甲回响与三曜流转

### 玄甲回响

体修的抱岳提供护盾，震步制造失衡，丹修负责恢复。永久分支把护盾实际吸收的敌方伤害存为藏劲，上限按体修最大生命的一定比例设定。过期护盾、未受伤的盾和自伤不产藏劲。

| 机缘 | 效果 | 防循环约束 |
| --- | --- | --- |
| 返震  个人 | 下一次普攻消耗藏劲，形成一次固定系数冲击 | 反震不触发反震，不把受击原伤害再次套全部乘区 |
| 护脉  个人 | 释放藏劲时，给另一名最低生命队友小盾 | 每 4 秒最多一次；来源独立登记 |
| 并肩守御  全队 | 护阵指令同时给符合条件的队友短效小盾 | 共用指令冷却；同名全队效果不叠乘 |

循环是让前排承受可处理伤害 → 蓄劲 → 普攻反击 → 保护后排。优势是稳，代价是击杀较慢。首领蓄力破盾仍要求打断或转守；不能仅靠堆盾永久无敌。护盾破裂事件必须带 shieldInstanceId，每份护盾最多产生一次破裂触发。

### 三曜流转

剑、符、丹等门类各自具备可独立使用的主动技能。符修记录真实施放留下的阵纹。构筑奖励轮换和适时保留技能，额外跳跃与自动追加不被算成一次新施法。

| 机缘 | 效果 | 防循环约束 |
| --- | --- | --- |
| 异法同鸣  全队 | 不同弟子接续真实施放技能时，为指定符修加 1 层阵纹 | 共享每 2 秒一次；绑定持有人，不能给所有符修无限复制 |
| 走脉成符  个人 | 消耗 3 层阵纹，下一次符法多跳一个目标并附有限失衡 | 跳跃不产生新施法事件；首领按韧性减效 |
| 三曜合拍  全队 | 3 名不同弟子在窗口内各施法后，降低下一轮有限次施法成本 | 共享每 8 秒一次；有次数与持续上限，不降低至负费用 |

循环是调整自动技能优先级 → 保留治疗或打断 → 凑齐轮转 → 群控与续航。减员、禁法或持续打断会破坏组合，所以每人仍保留基本作战能力；六人队也只按共享触发预算结算，不让额外人数造成无上限的连锁。

### 构筑的实际验收

四套成熟构筑、两两混搭和朴素配装都要测试。相近投入下，各成熟构筑通关率差先观察能否控制在约 10 个百分点内；普通难度不要求指定稀有卡。用至少 1 万个远征种子检查合法三选一、核心/补件保底、空池与减员适配。试玩记录弃选率、三张都不想要的频率和第 5 次选择前是否出现明显联动。这些是待执行目标，没有实测结果。

## 16  探索区域首领与战利品

区域探索由短路线、岔路抉择、普通战、精英战、营地和首领构成。出发前展示危险级、预期耗时、补给、撤退条件和已知环境；收益展示类别与保底进度，不把所有奖励精确到破坏探索感。

| 区域 | 资源与环境 | 首领机制与经营联系 |
| --- | --- | --- |
| 青岚外山 | 药材、木石、低阶法器；毒雾和狭道 | 千藤妖木：束缚与藤核相连，打断蓄力或分队破根；检验净化与集火 |
| 赤砂古窟 | 矿材、火性药引、阵材；热浪与落石 | 赤鳞地蛟：护甲阶段与冲锋预告，诱导撞柱后破防；检验站位和补给 |
| 寒潭遗府 | 传承残页、高阶机缘；寒域与镜像 | 守府灵傀：镜像分担伤害、阵眼轮换、限时护心；检验技能保留与控制 |

### 首领不是血量更厚的普通敌人

每个首领至少具备一个可见预告、一个玩家可主动处理的机制、一次阶段变化和一种可理解的失败原因。首轮只增加一项新要求，再把它与既有经营准备组合。困难模式改变机制组合、空间压力和资源要求，而不是单纯把生命翻倍。

危险区域用图形、动作和文本共同提示；只靠红绿色区分不合格。暂停可查看技能说明和伤害日志。首次挑战前允许低代价侦察，收集弱点、环境与补给需求，避免必须先死一名弟子才能知道规则。

### 战利品和重复探索

奖励包括材料、法器基底、功法心得和事件线索。随机词条限制在少数可理解的属性池；装备主要通过基底、炼制和适配形成差异。稀有材料保底使用可见进度或收集碎片，不能让主线进度完全依赖低概率掉落。

通关区域可以委派低风险采集，但需达到明确战力与补给条件，只结算已解锁的普通收益，不代替首次首领战和重大故事。委派使用同一历法与资源规则；风险预告中包含可恢复损失，禁止后台突然永久杀死队伍。

### 失败后的下一步

撤退与全灭统一采用第 13 节的封存结算规则；治疗与重整使再次出征有成本，但保留基础生产恢复能力。地图设置营地与明示的撤退窗口。首领重试不要求重新刷完全部普通路线，已清理节点可适度简化；任何快捷重试也必须先清理旧 run，再建立新 run。

## 17  事件内容与长期变化

事件模板要把已有状态转成新选择。1.0 的 48 个模板建议分为生计 8、师徒与关系 12、修炼与机缘 10、外部势力 8、天候与灾害 6、传承与追忆 4；另设 12 个主线节点。模板、文本变体和状态组合分别计数，不能把换名字算一件新内容。

### 一个事件的数据合同

每个事件记录 ID、适用阶段、触发条件、冷却、互斥标签、参与人选择、预告、选项、直接结果、延后结果、日志文案与回归测试。随机只在符合条件的候选集中抽样；不在缺粮时连续刷三次只扣粮的事件。关键事件可延迟，达到危险阈值前停表。

| 事件例子 | 玩家选择 | 可追踪后果 |
| --- | --- | --- |
| 师父闭关前的授业 | 延迟突破教新人，或安排代理师父 | 老者突破窗口、后辈心得与信任发生取舍 |
| 药圃灵虫 | 焚毁受害地块，试验驱虫丹，或减产观察 | 粮药短缺、配方探索和环境变化；不直接全库清空 |
| 外宗借阵 | 借出阵材换人情，付费协助，或婉拒 | 当季防卫余量、后续采购条件和声望标签 |
| 弟子争夺洞府 | 排定轮换、公开比试、扩大洞府 | 效率、芥蒂和建造预算；每种方案都有可见理由 |
| 故人遗愿 | 留下遗物纪念，交给指定弟子，或用于护山 | 物品用途、继承关系和后代事件线索 |

### 主线与自由经营的关系

主线通过准备条件解锁，不设置逼迫新手按现实分钟完成的硬倒计时。三处封印需要不同能力：可靠生产、成熟小队、传承与阵法。玩家可先解决自己擅长的方向，终章前仍需补足弱项。主线推进会改变地图、事件池和外宗态度。

### 可重玩性来自选择

开局种子改变地块灵脉、弟子倾向、资源分布和部分事件顺序，但确保最基本的生产与突破路线可解。二周目可选择不同立宗条件与难度；继承奖励以典籍线索、外观与开局选择为主，避免数值滚雪球让后续全无压力。

内容编辑时优先做三条贯穿链：师徒传承、受伤与冒险、资源短缺与专精。每条链至少跨越经营、关系和探索两到三个系统。孤立弹窗奖励即使写得很多，也不能代替持续变化。

### 内容完成标准

每个模板必须有触发样例、无效条件、至少一次状态变化和后续可见回声；每条主线必须有低运气可通路径。首发所有文本使用稳定键名，提供中文与英文映射，英文缺项按键回退中文；中文基础词库必须完整，不把整段文案嵌在逻辑判断里。

## 18  交互信息层次与美术目标

主屏以宗门场景为中心。顶部显示年月、速度、关键资源和风险；左侧为弟子/事务列表；右侧为可收起的选中详情；底部为当前模式的建设或战斗命令。任何全屏管理页退出后保留镜头、选中对象和暂停状态。

| 界面 | 必须立即回答的问题 | 交互验收 |
| --- | --- | --- |
| 宗门总览 | 谁在做什么，当前短缺在哪里 | 点击人物/建筑定位；告警跳到原因；可筛选待处理项 |
| 弟子详情 | 适合做什么，为什么不工作，距离突破还缺什么 | 需求原因、日程、师承、履历分层展示；批量调岗 |
| 突破准备 | 付出什么，成功/死亡风险多少，失败后怎么恢复 | 风险分项和材料预留；最终决定前确认不可逆代价 |
| 战斗与结算 | 危险从哪来，命令是否生效，损失为何发生 | 预告清楚；暂停能下令；日志与伤亡有来源 |
| 宗门史 | 谁带来了变化，传承给了谁 | 按人物、年月和事件回查；死亡人物仍可阅读 |

### 可访问性与输入

桌面浏览器为 1.0 首要平台，1280×720 到 1920×1080 为初始布局测试范围。文字大小可调至 125%/150%，不让固定高度截字；支持键盘聚焦、空格暂停、Esc 返回、可改快捷键。关键状态不能只靠颜色、音效或悬停；提供文字标签、图形差异和可点击说明。

提供减少动态效果、屏幕震动开关、闪烁限制、音乐/音效独立音量和静音后等价提示。管理页用语义化 DOM；Canvas 场景需有可键盘访问的对象列表作为替代入口。手机触控可列后续目标，不承诺桌面版自动缩成完整可用的手机游戏。

### 首发中英双语与逐键回退

默认语言为 zh-CN，设置可即时切换 en，无需重开战役。所有玩家可见文字均通过稳定键映射，包括界面、技能、天赋、状态、剧情、日志、悬浮说明、空状态与错误信息。英文某键缺失或为空时只对该键回退中文；中文缺键是内容校验失败，不允许向玩家显示裸键。

消息采用完整参数化模板，包含数量、人物、技能和数值占位，不能拼接中英片段；英文复数与数字格式按语言处理。人物自定义名保留原值，系统名称按 ID 映射。保存内容 ID、事件键和参数，不保存本地化名字；语言偏好独立于战役存档，切换语言不改变随机数、构筑或战斗。

### 统一的国风视觉规则

角色美术采用二次元 Q 版头像与插画，场景内采用统一的 Q 版像素角色与动作。两者共用人物比例、服饰剪影、法器形状和调色板；建筑与地表保持同一俯视像素语汇，远景保留简化的淡彩山水层次。石青、赭石、米白和墨色构成基调，职业靠工具与轮廓识别。核心人物、建筑组与妖兽原创设计。

选择像素动画是为了控制动作制作复杂度，仍需逐动作设计、清理和验收。角色动作从定稿种子帧生成或绘制整条序列，统一尺度、帧尺寸、底部中心锚点与透明背景，避免逐帧独立生成导致漂移。建筑优先静态图配云雾、旗帜和灵气程序效果；头像插画不直接缩成场景精灵。

素材验收在实际游戏尺寸进行：轮廓、色调、光向、武器形态、脚底滑动、透明边缘和首尾循环都要合格。免费素材可以提供底料，不能据此宣称已拥有一整套统一的国风美术。

## 19  技术架构与模块边界

推荐 TypeScript 单仓库，Phaser 承担地图、角色、战斗与 2D 表现，React 承担管理面板、表单和可访问 DOM 界面，Vite 负责开发和构建。模拟核心保持纯 TypeScript，不依赖 Phaser、React、浏览器时间或存储 API；框架版本在开工时锁定并记录升级策略。

首发可由静态站点托管，不需要后端、账号或多人服务。当前官方 React TypeScript 模板已采用 Phaser 4，API 文档标注 4.1.0；实施前仍须复核稳定版、目标浏览器和插件兼容后锁定精确版本。若采用模板，先检查默认构建统计脚本并选用 nolog 路径。此选型是针对浏览器与密集中文界面的判断，尚未做本项目性能基准。

### 从指令到画面的单向路径

用户输入生成领域指令 → 核心校验前置条件和资源 → 按固定步长更新世界 → 产生领域事件 → 更新只读快照与存档队列 → React/Phaser 各自消费需要的数据。渲染层不能直接修改余额、年龄、经验或战斗结算。

| 模块 | 拥有的数据与职责 | 禁止的依赖 |
| --- | --- | --- |
| sim 核心 | 时钟、人物、任务、资源、关系、修炼、战斗、随机数 | DOM、Canvas、React、Phaser、Date.now 和直接读写数据库 |
| content 内容 | 经过校验的功法、配方、建筑、敌人、事件与文本 | 带副作用的脚本或未经验证的任意代码 |
| Phaser 表现 | 场景对象、相机、精灵、动画、音效与输入适配 | 直接结算资源、偷偷推进第二套历法 |
| React 界面 | 选择、面板状态、排序筛选、指令提交 | 每帧复制整个世界；把领域状态当成另一份真值 |
| 平台适配 | 保存、导入导出、可见性、音频解锁、错误记录 | 绕过领域校验修改世界；静默上传玩家数据 |

### 模拟方案与扩展尺度

建议先用可组合实体与按职责划分的系统，保持简单数组/映射和稳定 ID；不为最多 36 名完整弟子引入复杂分布式架构。初始逻辑步长可设 20 Hz，表现目标 60 fps；生产、关系、需求按固定 tick 间隔错峰，画面插值。只有测试证明主线程存在瓶颈时，才把无 DOM 的模拟迁入单个 Web Worker。

React 通过稳定的查询快照订阅变更，只刷新相关字段；Phaser 用实体差异更新精灵。共享的是只读领域快照、命令和事件合同，不共享可变框架对象。所有取消/重试都携带命令 ID，防止双击或页面恢复造成重复事务。

## 20  技能天赋和状态的统一数据协议

技能、永久天赋、局内机缘、装备词条与状态统一使用受限的强类型积木。定义是可复用的内容配方，实例是某个来源在本次运行中产生的事实；DefinitionId 与 InstanceId 分开，避免删除一种状态时误删其他人物或装备带来的同名效果。

| 协议 | 关键字段 | 扩展要求 |
| --- | --- | --- |
| SkillDefinition | 标签、目标、前置、预约费用、提交点、冷却、施法时间、EffectSpec 列表 | 普攻与自动/手动施法同走合法性校验，不由动画直接造成伤害 |
| TalentDefinition | 树节点、前置/互斥、作用域、权重、Modifier/Trigger/GrantSkill | 永久树和局内池分开保存；卡面从同份数值与条件生成 |
| StatusDefinition | 身份键、来源合并规则、层数、时长、刷新/延长/独立/强者覆盖、驱散、周期效果 | 必须定义如何比较强弱、是否跨战斗和何时到期 |
| TriggerSpec | 事件、条件、目标、效果、几率、内置冷却、根行动/目标次数、允许间接触发 | 不直接改世界；只向后续队列提交效果命令 |
| ModifierSpec | 属性、固定值/加法百分比/独立乘区、来源、适用标签、优先级、上下限 | 来源账本保留；撤销来源只撤销它的贡献 |

### 白名单积木与执行边界

目标选择器先支持自身、当前目标、最近敌人、范围内敌人、最低生命队友和指定标签；过滤、排序、数量及同分仲裁明确。条件支持 all/any/not 与白名单字段比较。效果首批实现伤害、治疗、护盾、施加/移除状态、资源/冷却调整和受限追加动作；位移、区域、召唤等按验证进度再开放，内容不能引用未实现操作。

TypeScript 使用可辨识联合类型，外部数据配运行时 schema。构建时检查未知操作、ID 引用、非法数值、树循环、矛盾互斥、不可达节点与空机缘池。数据和存档不得包含 eval、任意 JavaScript、动态脚本 URL 或可注册执行器；“数据驱动”不能变成运行任意代码。

### 生命周期与持续时间是两根轴

lifecycleScope 取 character、run 或 encounter，控制最晚在哪个边界清除；duration 单独定义 infinite、逻辑 tick 或远征节点数。例如远征机缘产生的 5 秒护盾，可以属于 run 来源，同时具有 5 秒 duration。二者不能塞进互斥的单个枚举。

CharacterProgression 保存终身节点与配装；RunState 保存路线、机缘、offer 和结算状态；EncounterState 保存本场队列、状态、护盾与冷却。EffectInstance 记录 sourceEntityId、sourceDefinitionId、sourceInstanceId、scope、duration 与移除原因；统一生命周期管理器负责清理，不靠切换场景顺手清空数组。

## 21  统一结算流水线与复杂边界

所有普攻、技能、天赋和状态都进入同一结算流水线：输入意图 → 校验与预约 → 前摇结束重新校验 → ActionCommitted 提交费用/冷却 → 选择目标 → 命中与免疫 → 基础数值及修正 → 防御 → 护盾 → 生命变化 → 濒死保命阶段 → 倒地或死亡提交 → 不可变事件 → 收集后续触发 → 按确定顺序执行。

### 费用只在一个确定节点提交

请求施法先预约资源，使它不能被第二个技能同时花掉；前摇被打断、目标失效或施法者死亡时释放预约，可施加明确的短打断锁。默认前摇结束时才提交资源与正式冷却，飞行物已经发出后落空不退费，除非定义明示。施法后天赋监听 ActionCommitted，不能监听预约，防止反复取消刷收益。

### 事件与来源可追踪

DamageApplied 至少含请求伤害、减免、护盾吸收、真实生命损失、标签、暴击、rootActionId、parentEventId 和 triggerDepth。“命中后”“造成伤害后”“造成生命伤害后”是不同条件。eventId、actionId、来源实例和生成序号由核心序列器产生并存档，不使用动画回调或 Map 插入先后作为隐式排序。

触发排序固定为阶段 → 事件序号 → 优先级 → 持有人 ID → 来源生成序号 → 定义内效果序号。处理同一事件先冻结触发器快照，新生成状态不追溯监听该旧事件。日志记录触发链及拒绝理由，如冷却、前置不符、预算超限。完整伤害/治疗统计单独累积，UI 日志截断不能把战斗总量删掉。

### 快照叠层与回收

属性默认按基础加固定值 → 同组百分比相加 → 独立乘区 → 上下限 → 统一取整求值。进攻属性默认在施法时快照，防御在命中时读取；持续伤害保留施加时进攻快照，每跳读取目标防御。例外必须在定义显式写 snapshot/live。

状态写明 identityKey 是否含施法者、maxStacks、刷新/延长/独立/强者覆盖、数值随层数变化与驱散规则。expiresAtTick 使用排他边界：先移除到期，再做周期伤害。来源账本示例：甲光环、乙光环与丹药各加 10 护甲；甲死亡只清甲的 sourceInstanceId，另两份仍在。

### 死亡与触发链防失控

标准生命状态为 Alive → Downed → Recovered 或 Dead。生命归零先发 UnitDowned，不能发遗物/死亡奖励；可救援恢复。只有明确致死规则、放弃救援或预告过的致命攻击才提交一次 deathId 和 UnitDied。倒地停止行动并释放预约；死亡再结算遗物、师承与历史。后续状态和排队动作重验目标及来源，禁止已死来源继续行动。

默认 proc 不再触发同类 proc，使用 oncePerRoot、perTarget、内置冷却和白名单。最终保护预算先设每根行动深度 8、派生效果 64；超限截断后续派生并保存可复现诊断，不改骰子、不让页面卡死。这是工程保险，不能代替合理的内容设计。

## 24  数据合同存档与恢复

1.0 采用浏览器本地 IndexedDB 保存结构化数据，JSON 文件导出作为玩家可控制的备份。浏览器存储可能因配额、清理、隐私模式或设备故障不可用，因此不能承诺本地存档永不丢失；存档页要明确最近成功保存时间和导出入口。

| Battle | 实例 ID、参与者、逻辑 tick、技能状态、随机流、指令序列 | 允许安全暂停恢复；不得在载入时重新抽奖励 |
| UI 设置 | 语言、音量、文字尺寸、快捷键、减少动态、镜头偏好 | 与战役分开；坏设置可以重置而不破坏战役 |

远征必须保存完整 RunState：runId、路线/节点、offer ID 与选择、抽选流位置、已选机缘及持有人、已封存/未封存奖励、结算标记。Battle 还须保存待执行队列、状态实例、来源修正、到期 tick、冷却与触发预算；刷新后不得丢失构筑、重复结算或重抽三选一。

### 保存与迁移策略

保留手动存档、滚动自动存档和关键决策前安全档；建议 3 个战役槽，每槽保留 3 个自动版本。重大事务完成后排队保存，周期自动保存须去抖且不能阻塞画面。离开页面的最后一刻不作为唯一保存机会。

写入新记录并验证后再更新当前指针；失败保留最后成功版本。迁移使用 vN → vN+1 的纯函数，保留原始字节备份，迁移失败不覆盖原档。导入先做大小、JSON 结构、版本、ID 引用、数值范围校验，给出预览与覆盖确认后才能提交。

### 恢复与安全边界

检测同一存档被多个标签页打开，明确一个可写实例，其他实例只读或要求接管；不让两个时钟并行写同一战役。随机数种子与各流状态随档保存，战斗/事件抽样不依赖系统时钟。浏览器隐藏时暂停，回来恢复同一状态。

本地单机不设计反作弊服务，不收集实名或云端行为画像。错误诊断默认保留在本地，玩家主动导出时可先预览。将来加入云存档、联网或遥测，应单独设计授权、隐私和冲突处理，不能夹带在基础更新中。

## 25  性能预算测试与验收

性能数字是待验证目标。基准设备、浏览器版本、画质、地图大小和角色数量要写入记录；不能用高端机器的单次截图宣称全部设备流畅。建议以中档笔记本、1080p、128×128 地图、36 名完整弟子、约 200 个建筑/资源对象及 6 对 20 战斗建立夹具。60/200 人仅作可选压力实验，不扩大首发承诺。

| 类别 | 目标或验收条件 | 验证方式 |
| --- | --- | --- |
| 显示与响应 | 常规场景力争 60 fps；低画质保底 30 fps；操作应即时有反馈 | 固定相机和种子录制帧时间分位数；卡顿追踪主线程任务 |
| 模拟与经济 | 加速与逐步推进到同一 tick 得到一致状态；无负库存和重复事务 | 确定性回放、属性测试、跨 150 年批量模拟 |
| 存档 | 存读档领域状态一致；旧档可迁移；断写可恢复；坏档不覆盖 | 单元与集成测试，注入配额错误、损坏字节、版本差异 |
| 玩法闭环 | 从 4 人开局完成生产、修炼、三选一构筑、首领、传承、终章与继续经营 | 浏览器实玩记录；每一步有代表状态截图和问题清单 |
| 稳定性 | 反复切换场景不积累监听器；长运行内存不持续失控 | 进入/退出战斗 50 次，暂停恢复、隐藏标签页和长跑测试 |
| 可访问性与语言 | 中英界面在 150% 文字下无截断；键盘可操作；信息不只靠颜色 | 语言切换、英文长文本、缺译回退、键盘、缩放、静音逐项检查 |

### 测试金字塔与代表状态

单元层覆盖伤害顺序、寿元、突破后果、资源预留和配方。模拟层覆盖饥荒恢复、代际更替、长寿资源占用、极端性格组合和无补给出征。集成层检查 Phaser/React 生命周期与只读边界。国际化检查中文键全覆盖、占位参数一致、英文缺项回退，并在战斗、三选一、日志与错误页即时切换语言，验证状态和随机流不变。端到端测试用 Playwright 操作真实页面，不能只调内部函数代替玩家交互。

### 发布前必须通过的失败路径

原料在开工与取消间变化时不复制资源；双击确认不重复扣款；读档不重新抽奖

道路堵塞、全部高阶弟子受伤和连续坏收成后仍有可执行的恢复路径

风险页面上的寿元、概率和材料与实际结算相同；隐藏标签页不推进致死事件

所有资源和关键主线条件有可追溯来源；每个首领能以不同合理队伍通关

本地存储不可用时明确提示，玩家可以导出；发布包没有缺图、破音和错误许可

初次可玩资源压缩传输先以 10 MB、常规存档 5 MB、存读档 1 秒为预算，必须实测后调整；分区域和音频按需加载。验收报告区分“目标”“已测试”“未测试”“失败”。本策划没有游戏构建，以上测试尚未执行。

## 26  实施顺序风险与技能准备

按可玩的纵向闭环推进，每一步保留可运行的上一版本。用户提出的 30 小时以上指开发与验证投入的预期，不是游玩时长要求；当前不能用它推导固定交付日期，也不能用耗时达标替代功能验收。以下是依赖顺序和完成门槛，工时估算应在详细任务与首轮技术验证后更新。

| 阶段 | 交付物 | 允许进入下一阶段的条件 |
| --- | --- | --- |
| A 规则原型 | 纯模拟核心、种子、库存事务、时间和存档草案 | 加速/逐步一致；基础经济不锁死；可复现突破与战斗结果 |
| B 可见宗门 | 地图、6 名弟子、岗位、需求、6 类建筑、管理 UI | 玩家看得懂谁在工作；断路/缺料可诊断；暂停与保存可靠 |
| C 垂直切片 | 近山、8 技能、12 机缘、2 树原型、1 首领、关系、筑基和传承 | 从开局到首领/突破能连续玩；2 套构筑可启动；新增定义不改主循环 |
| D 完整战役 | 扩至 1.0 内容数、三地区、金丹/元婴、事件链和终章 | 通关与恢复路径实玩通过；新增内容不破坏旧档与预算 |
| E 发布候选 | 正式美术、音频、帮助、迁移、兼容性和许可清单 | 第 25 节关键验收通过；已知问题与保存风险明确；可回滚 |

### 主要风险与优先缓解

范围膨胀：先固定 24 人常规、36 人硬上限与四境界；新系统必须服务已定义循环，未完成闭环不再开支线

等待过长或衰老过快：记录决策密度、暂停比例和世代变化，先调时间成本，再调寿元；不靠礼包跳过问题

构筑失控：长期经济与触发链做性质测试，零成本递归、无限盾或永续控制先修复再增加卡池

美术不统一：先批准宗门小样和动作样张，建立导入规范，禁止多来源素材未经重绘直接混用

存档与时间错误：时钟唯一、事务唯一、迁移有测试；恢复能力放在早期而非上线前补做
