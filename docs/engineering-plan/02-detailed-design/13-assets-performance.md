<a id="assets"></a>
## 素材与许可管线

美术方向：用户偏好Q版动漫，并允许为动作序列采用像素方案；本方案选择Q版动漫立绘/插画配Q版像素世界精灵。两种载体共享角色头身比、服装/法器识别特征、国风色板和光向，不能混成无关联素材；俯视建筑/地面采用一致像素风，简化淡彩远景作为背景层。像素并不省略动作设计、修帧和验证。

建立style guide：俯视比例、像素网格/整数缩放、人物实际尺寸、帧尺寸/底部锚点/方向、建筑光向和VFX强度。先制作一名角色的立绘、地图精灵与完整动作对照样张，再扩资产。统一源帧生成/绘制动作，不逐帧独立生成导致漂移；按实际缩放检查像素边缘、脚底滑动和动作循环，说明UI立绘与地图精灵的映射。

AssetManifest逐文件记录作者、URL、获取日、许可文本/版本、原文件hash、改动、使用位置、审核状态。候选CC0/OFL不等于已下载可用；主角色/建筑/妖兽需原创统一。音频实听响度/循环/疲劳，透明边/脚底滑动在实际游戏尺寸检查。

<a id="budget"></a>
## 基准与测量

固定中档笔记本、浏览器版本、1080p、128×128地图、36弟子、约200对象、6v20战斗，记录seed/commit/设置。目标常规60fps、低画质30fps；记录帧时间分位数、长任务、堆内存与每系统tick耗时，不凭一张fps截图判通过。

初次可玩压缩10MB、常规存档5MB、存读1秒均是初始预算，区域/音频分批加载。性能退化先看profiling再减重复查询、寻路、过度渲染；不能削掉逻辑tick绕过规则。

<a id="worker"></a>
## Worker升级门槛

只有优化主线程后仍违反已批准基准，且模拟耗时占比明确时才提议单Worker。迁移需同输入回放同hash、序列化成本可量化、取消/暂停/存档边界一致、消息背压上限、崩溃恢复策略。未达触发条件保持单线程，workers目录仅为规划位置。

<a id="release"></a>
## 可复现构建与证据

开工锁精确依赖与工具链；干净环境依次typecheck→内容校验→单元/回放/集成→build→真实浏览器冒烟→资源/许可检查。保存commit、buildId、contentVersion、simulationVersion、saveVersion、产物hash、设备/浏览器与报告。

P0/P1、迁移失败、后台致死、基本经济锁死阻断候选。发布使用同一已验收产物，回滚需旧版本读取新档策略或可见备份恢复；不可只切网站版本。当前没有发布授权，TASK-049只做候选审计，TASK-050只交接方案。

每条验收记录状态target/not_run/passed/failed/blocked与证据位置，不可用“任务完成”替代测试结果。
