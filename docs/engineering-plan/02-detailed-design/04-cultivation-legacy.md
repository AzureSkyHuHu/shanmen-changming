# DD-04 修炼、突破、寿元与传承

状态：设计基线 / 待评审；未实现、未执行游戏测试

需求追踪：[REQ-009](../00-overview/requirements.md#req-009)、[REQ-010](../00-overview/requirements.md#req-010)、[REQ-011](../00-overview/requirements.md#req-011)

<a id="progression"></a>
## 人物进度合同

Disciple含年龄月、寿元上限月、境界、修为、理解、根基、心境、伤势、资质、技能熟练、主树与已获点数、关系稳定ID和记忆。所有年/月换算在边界进行；突破提高上限，不重置年龄。各境界基线见[源§6](../source/game-design.md#s06)。

Relationship保存信任/亲近/芥蒂、最近原因eventId、周期变化累计；Mentorship单独保存师徒、传授工时、已完成内容，不能因师父死亡抹除弟子已学。

<a id="breakthrough"></a>
## 突破事务

PreviewBreakthrough是纯查询，返回所需材料/闭关月数/因素分解/成功率及条件失败死亡率/风险条目/版本。ConfirmBreakthrough必须携带预览所依据的状态版本；过期则重新预览，不用旧风险扣新材料。

状态：Prepared→Reserved→InSeclusion→DecisionReady→Resolved。推进闭关消耗真实经营时间并检查补给；抽样只在确定阶段发生一次，sampleId、随机流前后状态和结果与成本提交共同保存。读档不重复扣费或重抽。普通失败输出可恢复伤势与准备建议；致死分支必须符合已预告条件。

不可逆结果前停表前台展示；隐藏状态不得默默跨过致死确认/呈现。具体确认交互属于游戏产品设计，不是对助手开发授权。

<a id="death"></a>
## 死亡与遗产

自然寿尽、突破致死和战斗UnitDied统一交给CharacterDeath事务，deathId去重。战斗UnitDowned不能进入本事务。顺序：锁定死亡事实→停止任务/释放预约→撤销来源→分发遗物与已授传承→修复活人关系引用→记录历史→触发继任/复兴检查。

死者档案不复用ID，读档可追人物生平。个人天赋和未传授熟练不无损复制。掌门是职务，任命后宗门建筑/库存/典籍继续；全灭展示损失及标准模式复兴或安全档入口，不静默销毁存档。

<a id="tests"></a>
## 验收

预览数字与真实结算同源；成功率与失败死亡率不混写。测试伤势/材料在确认前变化、闭关中短粮、同月寿尽与突破冲突（固定系统顺序明确）、重复deathId、师父死亡、最后一人死亡、读档恢复准备。关系每次变化可追到原因且不能无限送礼刷值。
