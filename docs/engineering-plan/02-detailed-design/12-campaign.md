需求追踪：[REQ-021](../00-overview/requirements.md#req-021)、[REQ-022](../00-overview/requirements.md#req-022)、[REQ-009](../00-overview/requirements.md#req-009)

<a id="events"></a>
## 事件合同

EventTemplate含ID、阶段、条件、冷却、互斥标签、参与者选择、预告、选项成本、即时/延后结果、历史文案和测试。模板、文本变体、状态组合分别计数；48模板分组数量只取源§17。

候选过滤后抽样，不为缺粮状态连续派不可恢复扣粮事件；重大事件先停表。选择事务重验成本/参与者，选项失效给原因和其他合法选项，不按旧面板强行扣除。延后结果有dueTick与唯一提交ID，保存后照常且只一次。

<a id="quests"></a>
## 主线和首领进展

QuestGraph为12节点有向图，节点含解锁条件、目标计数来源、奖励/世界变化和替代路径。三封印要求不同准备，顺序保留选择；终章同时检验资源/小队/传承/阵法，不由纯战斗力跳过全部经营。

首领首次胜利、稀有材料保底与碎片进度各去重。低代价侦察提供预告与补给信息，不强迫先死一人学机制；快捷重试不继承旧run状态。

<a id="recovery"></a>
## 失败、结局与继续经营

标准模式允许复兴或安全档；硬核开局选择且中途不暗改。终章成功记录结局/传承后进入可继续经营，不清空世界或偷偷开启无限数值继承。代际人物死亡仍有史料可查。

连续坏收成、主力全伤、关键师父死亡和不走某专精都须有可执行路线。先编三条贯穿链：师徒传承、受伤冒险、短缺专精；每链至少跨2–3系统并有回声，不以孤立弹窗堆数量。

<a id="tests"></a>
## 剧情与经济验收

从4人开局到三封印/终章/继续经营的有记录实玩；固定低运气seed也可取得关键材料；中途全灭、继任、迟到事件与非法成本覆盖。150年模拟寻找锁死，但最终可理解性必须人工玩验证。
