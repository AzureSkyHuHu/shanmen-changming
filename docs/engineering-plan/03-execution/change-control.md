# 变更与证据控制

## 单一真值
玩法源是冻结的[source/game-design.md](../source/game-design.md)；需求目录为工程映射；详细设计明确合同；tasks.json产生任务表与任务简报。不要只改生成后的任务表导致JSON与文档分歧。

## 变更步骤
1. 记录请求来源、需求ID、动机与影响范围
2. 判断是澄清、数值试验、内容新增还是破坏接口/存档的变更
3. 更新相关ADR、详细设计与任务依赖；重新跑链接/ID/无环校验
4. 内容变动提升contentVersion；模拟语义改变提升simulationVersion；存档形状变化提升saveVersion并增加迁移fixture
5. 验证新旧卡面、实际规则、日志与中英参数一致；附回放与实玩证据
6. 若用户未授权的新范围/部署/服务接入，暂停相应动作取得决定

## 回归触发
时钟/随机/排序改变：全确定性与存档回放；属性/触发改变：四构筑与来源回收；人物/死亡改变：传承/复兴；内容改变：schema/计数/空池/中英覆盖；UI改变：键盘/150%/英文长文本；版本升级：干净构建/兼容/旧档。

## 证据模板
记录项：任务ID、需求ID、commit、构建hash、三种版本、测试命令、seed/场景、设备与浏览器、结果状态、报告位置、失败原因、复审人。不得把本文件的示例或计划写成已测证据。
