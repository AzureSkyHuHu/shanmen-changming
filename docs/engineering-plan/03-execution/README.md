# 执行入口

## 当前能做什么
本包只交付设计。下一步先评审[TASK-001](tasks/TASK-001.md)的范围、run边界与环境，取得实现授权后才执行后续开发。TASK-002核验版本与工具链，TASK-003/004可并行，其后用依赖DAG推进。新中英需求由[TASK-051](tasks/TASK-051.md)覆盖；编号追加不代表最后才做。

## 日常用法
1. 读[阶段门](milestones.md)，选择前置全部完成且授权充足的任务
2. 打开[任务登记](task-register.md)的详细页，确认需求/设计段/模块责任
3. 先制作失败夹具与验收断言，再做实现，记录证据
4. 以任务为单位小批提交；内容/接口变化同时更新需求与设计
5. 阶段末按[QA矩阵](qa-matrix.md)实测，未通过不扩大内容范围

## 状态机
planned→ready（前置完成且获授权）→in_progress→review→done；任意进行态可blocked；删减范围用cancelled并说明。任务状态与验收状态分开：测试target/not_run/passed/failed/blocked。当前没有任何ready/in_progress/done实现任务。

## 并行边界
内核/经济、人物、战斗、内容、表现、持久化各指定一个接口负责人；同文件不可两个任务同时无协调写入。测试/内容可与稳定接口的实现并行，但不能把mock通过当真实集成通过。先完成内容能力再启用相关卡，先过切片再扩全量。

## 计划不是估时
“超过30开发小时”表达用户期待的项目规模。本包按成果与风险分解，不虚构交付日期。首轮技术验证后可另做带假设的估时，不能用耗时达标替代游戏验收。
