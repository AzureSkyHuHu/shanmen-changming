# v9 私有长生命周期运行实例

本片增加内部 `createPrivateRuntimeV9`，用于测量和摊销重复外部调用的来源认证开销。普通应用、ApplicationSession、World engine、codec、UI、内容注册和旧 `.3` 行为不变。它不是可导入存档能力、密码学认证或面向玩家的运行时。

## 外部入口与所有权

- 创建和 `replace(unknown)` 都先按数据描述符复制出完全隔离的 JSON 树，再执行完整 `.3` 来源验证、支持范围、实际硬上限和有限教学策略检查。未知协议、getter、非 JSON 形状和已有活动授课不迁移、不剥除、不取消
- 实际合格但未来余量不足的来源可进入 recovery-only 实例；不能因此走空闲快路，任何推进/命令仍需原有限恢复准入证明
- 只冻结已经复制的自有树。外部浅冻结、深冻结、同一个引用、ID 和上一份返回快照都不授予来源信任；Proxy 的反射 trap 仍可对调用方对象产生副作用，因此不声称外部复制是原子快照或能识别所有 Proxy
- 实例通过闭包保存根、私有 WeakSet、精确评估、空闲保守向量、代数、发布号和安全停止。API 没有 World 参数的推进入口，没有可注入证书、可信标记、所有者分类或验证回调
- 每个方法先设置重入保护，之后才反射未知输入。复制阶段抛出的外部异常直接返回固定错误，不执行 `instanceof`、读取 message 或重新读取原始输入。递归调用 advance、replace、command、snapshot、invalidate、close 都只返回 reentrant

## 精确证书与跨调用空闲证明

精确 StrictAnchor 绑定特定的私有根及 generation。另一种独立类型 IdleCarry 只能保存五标量证明，不能传给完整候选决策或释放前态比较。

空闲范围与已验证的批次原型相同：只有 simulationTick、calendarTick、施工 revision、宗门生产 revision、研究 revision 每次各加一。每个调用都重新检查无活动工作、无规划/维护到期、无月结/生日/死亡/成长边界以及安全整数等结构条件。其余自有冻结子树原样沿用；整封包 UTF-8 增量来自五个十进制数的准确宽度变化。继续保守保留旧的未来预算，不把预算缩小冒充真实释放。

符合条件的重复 `advance(1)` 不再复制和认证调用方 World；每次仍执行逐刻的证明与容量差分。源首次建立时的全量认证成本明确保留。

任何活动工作、月结/生命周期边界、命令或快路不确定情况，仍准备完整候选并完整查询容量，再使用与原严格入口共享的原样决策。若手里只有保守 carry，先对当前根重新完整评估；已有相同根的精确证书可沿用。正常候选失败后，关闭可选开工/续费的候选从同一个未发布前态重新准备。原严格 stateless 入口仍是差分基准。

严格候选也先复制再冻结，防止将内部执行器可能借用的常量/目录引用宣称为实例所有。此选择可能增加活动工作的复制成本，必须单独测量，不能用空闲成绩替代。

## API 与生命周期

- `advance(steps)`：只返回推进数、临时测量、stopped 和 stamp；不自动返回整棵世界。逐刻发布已经验证的完整边界，后续失败保留前面已成功的刻
- `command(unknown)`：描述符复制后沿用原命令的精确重试、冲突和拒绝顺序。新候选经严格门禁后才能发布；容量拒绝不记录候选变化。原引擎本来会记录的普通失败回执仍按严格结果保留。返回命令结果另行复制并深冻结，不能通过 receipt 结果引用修改私有世界
- `replace(unknown)`：在独立 ownership set 中准备全新来源，全部成功后才原子交换。失败保留旧根、精确证书/carry、快照缓存、stamp 和停止状态；成功增加 generation 与 publication、清空旧派生状态和停止
- `invalidate()`：增加 generation，丢弃精确证书和 carry，不改 World、publication 或停止。下一次读取世界的操作只重新认证一次；若尚未发布，已有隔离快照仍可沿用。只返回逐操作测量，没有跨调用的语义计数缓存
- `snapshot()`：按需创建独立的深冻结 JSON 副本；同一个发布边界缓存该副本。返回快照从来不是内部根，即使深冻结也不是可转交给别的实例的认证证书。复制失败不关闭、不发布、不清掉世界，允许干净重试
- `close()`：释放根、证书、carry 和缓存，增加 generation。不会保存、自动取消工作或执行资源结算。再次 close 及以后所有操作明确返回 closed

stamp 只是每个实例内部的观测序号，不是跨实例身份或授权凭证；不允许调用方提交 stamp 来证明世界可信。此首版没有 exit-with-snapshot，避免导出失败与关闭之间的复合语义。

失败推进会锁存私有安全停止，不往 World 增加暂停、诊断或失败回执。重复推进不会自动重试该停止；invalidate 保留它。真正发布的恢复命令或成功 replace 清除停止，命令重试/冲突/拒绝不清除。暂停/速度等时钟控制暂时只通过完整验证的 replace。

## 文件边界

- `runtime-owned-internals-v9.ts`：从原空闲入口原样抽取描述符复制、自有冻结和五标量证明；没有公共 re-export
- `runtime-decision-v9.ts`：从严格入口原样抽取完整候选判断及其必要 source/refusal predicates；没有修改释放比较顺序或授课策略
- `runtime-idle-v9.ts`、`runtime-capacity-v9.ts`：旧公开签名和执行算法保留，只改内部 helper 的导入位置
- `runtime-instance-v9.ts`：私有持有者；未接入其他生产模块

没有修改共享 canonical counter、其 helper、成长/教学协议、保存入口或 ApplicationSession。

## 测试与测量范围

新增测试使用严格 stateless 门禁作为 oracle，覆盖重复单刻和批次、256 条真实修炼命令历史、真实施工/研究/药品/护理/采矿/旧生产混合工作、维护、月份/生日/寿尽和死亡归档、突破义务、余量不足恢复、最后修订、命令重试/冲突、教学拒绝、源突变/浅冻结/深冻结、跨实例/旧快照隔离、原子 replace、invalidate、重入 Proxy、getter、敌意抛出对象、close 和导出故障。

性能脚本保留原三种模式，另逐场景报告：

1. 冷创建与完整 replace；复制、验证、计量和冻结都在其计时内
2. 同实例连续 20 次 `advance(1)` 和连续 3 次 `advance(20)`；明确请求与实际推进刻数，死亡暂停不冒称执行完全部请求
3. 新命令、同内容重复及同 ID 不同内容尝试；完整输出实际命令结果，余量拒绝导致没有持久回执时不冒称精确命中
4. 首次快照和缓存快照、invalidate 与下一次重新认证推进

每个序列另外记录其初始化与末尾导出的耗时；它们不藏进夹具准备费用。严格 oracle/JSON 等价比较在计时之外；真实工作夹具仍使用真实操作形成，基础库存、月内边界和诊断字节压力保持原有明确标注。没有墙钟阈值单元断言。

本片作者没有运行测试、类型检查、构建或基准；统一集成负责人执行并记录终态。文件存在不表示通过。重复空闲成绩不能证明活动工作、完整应用 20Hz、3 倍速、36 弟子、长期年代、浏览器渲染或移动端已经达标。

## 合并负载补测

另加 `heavy-mixed-work`：在真实制药后的世界实际接受另外 256 条修炼命令，并核对完整回执数量，再真正开始护理、采矿和旧木板生产。历史压力和三人活动工作发生在同一个 World，不拿重历史空闲与轻历史活动的分别成绩推断合并表现。仍不代表 36 人负载。

可用 `node tools/benchmark-v9-runtime.mjs --samples=20 --scenario=heavy-mixed-work` 单独测量这个场景；未提供过滤器时测量所有场景。过滤只改变被测场景，夹具准备费用仍全部单独报告；不会略去该场景的冷创建、替换、重复推进、命令或快照测量。

## 实测基线（2026-10-02；尚未完整仓库验证）

双类型检查和139项相关定向检查通过47.90秒。原7种情景的20样本基准与新增复合负载基准均通过逐次结果一致性检查；创建、替换和导出独立计时，不隐藏到每帧推进数字中。

- 256条历史的空闲连续单刻p95约0.0465毫秒，冷创建p95约41.72毫秒，首份导出p95约4.39毫秒
- 普通三人混合工作连续单刻p95约24.62毫秒；活动候选仍每刻完整评估，没有跳过记录或容量准入
- 缓存导出包装不再递归扫描整个已验证冻结快照；返回小包装，旧快照仍隔离且不可写
- 寿尽情景的20次调用仅实际推进1刻，其余因真实暂停不推进；不能把包含19次暂停的低分位耗时当成死亡处理本身的速度

新增 `heavy-mixed-work` 将真实付费制药历史、256条新增真实修炼命令，以及疗伤/采矿/木板三人并行工作放在同一世界。独立命令 `--samples=20 --scenario=heavy-mixed-work` 检查真实组合，而非分别展示轻工作与重空闲：

- 原记录型单刻p95约41.06毫秒
- 无状态严格容量入口单刻p95约229.89毫秒
- 私有实例连续单刻p95约120.88毫秒、最大158.80毫秒；冷创建p95约112.43毫秒
- 单次20刻实例调用p95约2310.80毫秒，不能满足流畅目标

结论：长期私有所有权解决重复冷空闲认证，但没有消除“长历史＋实际工作”的验证开销。该复合负载仍是激活前的明确性能阻塞，正在独立定位；本片不声称20Hz、3倍速、完整人口/地图或玩家界面已验收。
