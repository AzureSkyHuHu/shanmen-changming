# Registered v8 exit admission: runtime candidate

This is an additive candidate connected only to the v8 core entry points. Default factory, App, parser, v7 and UI activation are outside this slice. The existing standalone derivation is documented in [registered-exit-budget.md](registered-exit-budget.md).

## Complete command boundaries

`covered-capacity-v8.ts` is the shared leaf for the older management/progression/clearance dimensions and effect-ID grammar. The previous runtime-capacity export remains available. The exit certificate imports the leaf rather than importing its own runtime caller.

A complete registered departure or active-run command candidate is assessed after the adapter, World receipt, pending-pin cleanup and any estate settlement. Publication needs the full paid-exit vector, including F + 2R + C + P + X. Legacy-v2 continuation retains the preceding covered-capacity branch. The public assessment still authenticates data-only encoding and the complete World, including domain replay.

A rejected candidate leaves the source World, resources, IDs, RNG and run unchanged. Registered player IDs must fit the entire derived effect ID, without truncation or renaming. No source protocol is relabeled.

## Real reservation discharge

An imported source may have a composed-reserve deficit while its actual save still fits. A real required transition can discharge its obligations only when every candidate dimension either fits its limit or is no larger than that source dimension. Actual wire bytes and the actual R/C quotas remain hard limits. A new funded source cannot publish a new deficit through this rule.

Recognized evidence includes an actual prepaid checkpoint admission/commit, real retreat or terminal defeat, actual member death, committed terminal history and any conditionally required shared proof, exact remaining mandatory travel, a complete required inventory clearance, a cancelled production record/pin, or the existing typed progression discharge verifier. Optional encounter entry, reward choice and rerolls have no generic release exemption. Automatic cancellation checks its authenticated `Cancelled` terminal pin; manual cancellation checks its historical transaction. Merely dropping an owner from a list is insufficient.

## Tick ownership and cost

Each registered `advanceTicksWithStatusV8` invocation authenticates the source with the public assessment, then detaches it and recursively freezes its owned JSON snapshot. Its WeakSet is local to that synchronous invocation and only avoids walking already-frozen shared subtrees. Nothing is cached by a caller's mutable World reference or read from saved certificate fields.

Ordinary ticks with unchanged obligations use the exact canonical World byte delta and the actual WorldEncounter and run sizes. All prior row/reader/ID/revision bounds remain in the local vector. Simulation headroom increases during frozen-calendar combat using the small tick delta before a checked addition, never a sum of two large absolute counters followed by subtraction; exact travel reduces the remaining mandatory calendar window. Any obligation, identity, resource, sequence, receipt or domain-history change causes full strict re-assessment. Manual transaction changes also force this strict path: the cancellation fallback preserves activeTicks and worksite/storage fields in multiple future placements, so their reservation delta is not just their current World byte delta.

The active run's existing `run-build` progression owner includes an explicit shared scalar width replacement for simulationTick and calendarTick. The incremental path spends exactly one copy of their actual digit growth. Other duplicated progression allowances remain conservative; the unrelated general 1 MiB margin is retained. The path falls back to strict re-assessment if its conservative accumulated vector reaches a limit.

A refused next tick returns the previous complete boundary with a save-capacity pause when that pause itself fits. It never publishes the rejected controller/RNG, and does not report the refusal as an invariant error. Only explicit kernel capacity failures, the existing archive capacity errors, and the exact combat engine capacity-message vocabulary are classified as capacity stops; unrelated RangeErrors remain invariant diagnostics. Real recovery commands remain usable. Unknown registered imported sources return the original object and bytes with an unbounded-obligation status, without adding an error or rewriting history.

## Queue policy

A saved active registered optional queue is explicitly unsupported by this fixed exit proof. Tick advancement preserves it unchanged. Public dispatch never deletes queue rows based on `existingQueuedCommand`; only the existing private runner consumes one exact occurrence after application on its supported paths. Conflicting duplicate IDs, distinct later commands and unrelated callers' context flags cannot turn an unknown saved queue into an empty certified one. This slice does not promise an atomic multi-command recovery for such imports.
