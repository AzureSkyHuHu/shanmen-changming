# v10 丹房升级领域阶段

日期：2026-10-02。范围：冻结合同 stage B 的内部领域实现；不是可玩的 v10、存档准入、迁移、发布或完整游戏验收。

## 实际实现

- 不改旧 `.3` 内容、历史或入口。新升级域保留独立 schema/protocol、精确全体字段、局部 `1,3,5…` 编号和不可删除的工作/回执历史
- 真实预留石6/木板6，沿已有四向导航先到仓库再到丹房入口；每格4刻，到达边界没有工时，所有任务共享调用者提供的寻路预算
- 第200有效刻配对消耗石3/木板3；第400刻余款、成对 committed 结算与 completed/resultLevel2 同次候选提交
- 0–199取消退剩余6/6，200–399取消退3/3，已耗部分不返还；工人保留当前安全位置，任务导航清空，没有传送、重建建筑或导航版本虚增
- construction 建筑始终原L1，完整来源、位置、朝向、完工时间和首期维护到期不改。等级从真实升级完成派生；维护阶段同刻完成仍L1，之后的生产边界为L2
- 全程独占 workerId、buildingId seat 和入口坐标；未终态生产即使释放工位、正在送货仍阻止该建筑升级
- 有效工时以有界、有序且可合并则必须合并的span保存；检查点时间从第200/400个有效刻按span推导，无法用自报工时或库存取代工作/支付证据
- 管理上下文、可劳动/在家/存活投影、入口、仓库、维护、材料、全体本地工作和局部取消余量均参与候选检查。没有材料以外阻塞自动退款或承诺一定最终完成
- 精确玩家commandId语法为 `[A-Za-z0-9._:-]{1,128}`，危险名称、斜杠/system命名空间、额外price/level/provenance字段拒绝。重复完整body返回原接受结果，ID异body冲突
- 描述符先行有界检查拒绝getter、symbol、洞、exotic prototype、undefined、非安全整数及共享别名/环；Proxy自身反射执行/分配仍不是可由本地预算隔离的能力

## 固定接口和认证层次

`upgrade-runtime.ts` 导出冻结 `applyValidatedSectUpgradeCommandV10` / `tickValidatedSectUpgradeV10`。两者是内部固定阶段，前提是新root已经完整认证输入；返回候选也必须由root完整认证并量容量后才能发布。它们不冒充外部安全边界，不接受callback、信任flag或caller certificate。可复用纯叶不伪造v9 World、不隐藏reservation、不降级L2记录。

`applySectUpgradeCommandV10` / `tickSectUpgradeV10` 是单独命名的安全独立领域包装器，对输入和输出执行升级领域检查，并可使用真正版本认证的历史人物引用来源。领域通过仍不代表World、培养/构筑、余额来源、六所有者、生命周期或4MiB/reader/未来义务通过。

`upgrade-validation.ts` 的 `validateSectUpgradeRecordsV10` 依次消费完整construction记录、全维护历史的结构/全部L1结算、真实研究DAG及工作证据、每个丹房L1图纸在放置/开工前的基础药理来源，再认证自己的升级记录、账本、span、回执、来源和冲突。完整成对预留账本始终可见，借已有账本检查两个真实checkpoint的名字、顺序及精确金额。

`upgrade-level-records.ts` 仅依赖类型，提供 `sectBuildingLevelAtFromUpgradeRecordsV10`；固定phase union避免维护/升级验证循环。`upgrade-queries.ts` 的冻结查询为已认证记录的只读叶。`*FromIsolatedFrameV10` 对应包装器可先执行独立领域验证，status额外验证最终L2维护结算。查询不产生授权、不占资源。

升级tick接收时，调用者已经前移唯一construction投影时钟，两个当前时钟必须等于context。升级没有自己的持久lastTick；全局每刻恰好调用一次、已暂停时不推进工作由root编排。局部工作/访问避免同刻重复加工，但不能凭无单独时钟的数据形状认证调用次数。

## 明确保留的集成缺口

- 工人的duty、授课、永久构筑锁、旧自动生产与World位置/traveling映射须由新root认证，不能单凭投影布尔值授权
- 现阶段不执行系统死亡取消。pending/dead工人的升级tick拒绝，因此399不会在清理前成为400；序列化death reason及system commandId不能自行授权。必须先有绑定精确源→候选生命周期转换及World expiryPending/died镜像的固定证据路径，再开放forced cancel；历史人物上界来源不足以授权当前死亡操作
- 死者终态/归档历史引用可通过版本认证历史source参与独立record检查；没有source的安全包装器有意拒绝消失工人。内部冻结阶段不再无source重跑所有旧历史，从而不将有效退休历史误拒绝
- construction的普通数值、旧域价格/研究证明可复用；全六域反向owner闭合、全部命令/实体跨World历史唯一、L2生产与两配方护理、培养clock与life-cycle、真实World未来余量由后续固定root负责
- 128 jobs、256 receipts、384 paired claims、401 visits、400 spans和局部取消revision上限只是局部有限容量，不是完整envelope证书，不声称无限经营
- 新codec、quiet迁移、独立DB、Session/UI、真实浏览器、生产构建和发布不在本领域交付范围
