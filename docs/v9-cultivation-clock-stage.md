# 内部 v9 .3 修炼时钟证据

本片仅适用于新鲜未注册 `.3` 世界，不补造 `.2` 历史，不修改 v3/v7/v8 的公共存档与领域校验器。未接入玩家界面或完整游戏验收。

每次真实月结或生日同步导致修炼修订递增时，在 World 专属 cultivationClock 中原子保留一行类型、实际 tick、月结前修订号和实际 action 来源。相同刻的生日合并，月结优先，不为每个人重复记录。

校验从已有成功命令回执、归档权限回执、疗伤效果和新增时钟行导出完整的修订所有者集合，逐一覆盖从零开始的连续修订。排序只遍历有限保留记录，不按不可信的巨大 tick 或修订号循环。月结/生日的覆盖按现存与归档身份的生辰、生命边界进行算术核对。

自然休养取消必须引用实际月结行，由此定位真实的历史修订边界，再核对休养模式与天赋授予。寿尽或突破待决定会在工作前暂停整个世界：同刻不允许疗伤工作；待决定期间不得伪造时间推进；死亡确认、突破处理或取消必须在相同决定刻结束。死亡后的无事件“成功空操作”也不能伪造额外修订。

本协议有8192条时钟行的明确上限。只对当前同步生日开局，8192个月覆盖约682年；未来生日错开会共享并更快使用此额度，不能承诺任意人口下相同时长。容量耗尽在运行真实变更前拒绝，保留原完整边界；即时取消不申请时钟行。不删除、压缩或悄悄改写历史。

容量查询同步升级为 `.3`：当前时钟记录只在完整封包计量一次；已承诺的有限成长时段和生命周期触发记录另有类型化行/字节/解码节点余量。无界等待、任意新月份和真实运行时准入仍不由只读查询授权。

这证明序列化结构、来源与时间顺序一致性，不是密码学防篡改，也不声称逐刻重放所有历史伤势。codec、Session、界面、远征退出与完整实际验收仍有独立关口。验证结果由开发状态按真实完成结果记录。
