# v10 实际单刻流水线接入私有运行实例

## 本次范围

私有 `createPrivateRuntimeV10()` 为每个实例创建独立的 `createOwnedTickPipelineV10()`，在原标量空闲分支之后尝试真正的活动单刻。新流水线本身执行固定 reducer、完整候选记录/容量检查及原跨边界记录比较；不把任意调用者候选、冻结标志、DTO、诊断或 assessment 当作执行证明。

公开候选门、命令门、恢复规则、保存/导入入口和普通玩家入口未被替换。该集成不注册 Session 或界面，也不根据叶基准宣布浏览器、20Hz、3倍速或移动端性能通过。

## 三条路径与顺序

1. 先执行现有标量空闲入口和续行，保持 `fastTicks` 原义
2. 空闲不适用时，只在当前精确根具有完整 future-fit 且无授课时尝试独占实际单刻捕获。该条件只用于提前排除；工厂仍完整复制和认证自身的来源
3. 每个实际刻按以下顺序尝试：独占正常 → 原严格正常 → 独占无可选增长 → 原严格无可选增长。成功即结束该刻；没有略过原严格正常去选择无可选增长

独占工厂只接受 ordinary-fit 结果。正常叶返回 `null` 时，原严格正常仍可能是唯一能认证的解除义务/恢复结果，因此它必须优先于任何 fallback。严格正常成功会清除独占游标；仅当它失败，且工厂仍精确绑定同一来源，才允许独占无可选增长。从头到尾，所有尝试读取同一完整来源边界。

叶 `null` 或叶调用的意外异常都只请求严格路径，不能单独变成安全停止；异常不读取 `message` 或原型。只有原严格尝试也失败，才按原规则锁存最终停止。已发布的较早刻保留，失败刻不发布部分时钟、路径、资源、随机流、回执或维护结果。

## 身份、发布与失效

- 独占游标是闭包中的根对象身份与 generation；工厂从不接受这个游标或外部 assessment 作为参数
- 捕获成功得到独立且完整认证的等价新根；外层同时采用根、精确 assessment 和游标，清空展示缓存，不增加 publication
- 实际刻成功返回的是该工厂刚执行并完整检查的冻结结果；外层一次性采用根、精确 assessment、游标，清空展示缓存与空闲状态，再增加 publication/advancedTicks
- 完工后可以回到原标量空闲分支。空闲捕获成功时清除实际刻游标，绝不把保守空闲余量传给实际刻工厂或候选门
- 所有命令、时钟控制、replace、invalidate、close，包含既有清除证明的无写入/失败调用，均清除实际刻游标。异常与最终安全停止也清除它
- snapshot、固定查询、失败查询及无效 advance 参数不会清除游标。它们不改变实际根或代次，不创造任何新命令权限
- 暂停/锁存停止仍先由外层原有检查处理。授课及恢复专用来源仍走原严格门

## 指标

原字段保留明确范围：

- `sourceChecks`：外层 `checkSource` 调用，不包含叶自己的完整查询
- `candidateChecks`：原严格候选门调用
- `normalCandidates` / `noOptionalCandidates`：原严格 wrapper 准备次数
- `fastTicks`：实际发布的标量空闲刻
- `exports`：显式完整快照导出

新增四个独立字段：

- `ownedCaptures`：实际单刻工厂的捕获尝试
- `ownedNormalAttempts` / `ownedNoOptionalAttempts`：两个固定实际单刻入口的调用尝试，包含拒绝
- `ownedTicks`：该工厂成功且由外层实际发布的刻

这些指标不是完整 CPU 工作量或“零完整检查”声明。成功捕获和每个独占发布候选仍要求叶自己的完整容量/根记录检查；同一失败刻可能执行独占与严格两次准备。冷捕获、慢恢复和叶拒绝路径需要分别测量。

## 测试范围与当前证据

新增 `v10-runtime-owned-integration.test.ts`，28 项覆盖：

- 实际活动采木的多次/批次完整 World 与原严格入口差分，跨调用捕获复用，标量路径优先
- snapshot、成功/失败/反射重入查询不丢游标；所有原有证明失效入口及代次/根替换重新捕获
- 不同 owner、借用方法、外部冻结快照、关闭后访问与展示缓存隔离
- 独占捕获/正常拒绝或敌意异常回原严格正常，严格正常成功时不执行 fallback
- 真实自动增长容量拒绝的正常→严格正常→同源无可选增长顺序
- 真实数值耗尽的双失败、前一个完整刻保留、安全停止保留、外层可重入保护
- 实际已付费教学仍走严格正常
- 真实研究历史后的升级开始、199→200 半付费、399→400 L2、L2 维护、替代药物来源和照护完工
- 升级完工回空闲、恢复专用真实升级完工、寿尽先取消升级并保留领域暂停

旧经营历史通过共享真实 reducer 夹具得到；其基础库存资助是明确测试条件。月结/寿尽测试的合法近边界初始设置不是跨越时间的模拟证据。新测试不伪造升级终态、维护支付或回执来源。

基线测试改动仅位于：

- `v10-runtime-instance.test.ts`：原 exact metrics 对象补齐新增零字段；真实 fallback 指标按两条路径分别计数；原敌意异常注入同时连接新增固定 raw stage helper，保持原“无发布、异常零读取、停止锁存”断言
- `v10-runtime-idle.test.ts`：仅调整真实边界转由实际单刻处理后的指标预期；全部 World、停止、顺序、旧快照和生命周期断言保留
