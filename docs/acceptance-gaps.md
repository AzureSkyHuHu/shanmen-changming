## 必须闭合的玩法链条

1. **持续经营**：觅谷、种谷与做饭已接入真实生产；v7候选已完成有界自动工作、空间预算与库存目标界面，并通过1000循环与944项整树检查；真实浏览器长期经营与整体平衡仍须验收
2. **真实成长来源**：装备、知识、师承和遗物必须能从实际进度取得。已有空面板/底层授予 API 不等于完成了掉落、学习、继承的玩法；不能为了好看填入不存在的奖励
3. **代际延续**：招募与弟子补充、失去关键人物后的恢复方式、学艺/装备/遗物的真实传承，需要与战斗、职务和宗门库存接通
4. **构筑内容**：线上机缘仍12/48；另有48项候选目录通过执行与静态测试，其中额外连锁失衡尚未支持，实际可执行47/48。移动、区域与召唤已接入v5。候选还须完成跨成员适配筛选、真实旧目录迁移及平衡，不能把未接入目录当作已开放
5. **战役与重复游玩**：当前路线是首个贯穿案例。需要有实际目标、不同机制的后续挑战、可识别的完成状态，以及足够变化的构筑与队伍选择
6. **风险的可对策性**：倒地不等于永久死亡；危险机制、救援、护卫、撤退与伤势恢复必须给出明确因果。当前紧急撤退未实现，界面应保持不可用，不伪造成功撤离

## 工程与体验验收

- 新游戏/继续游戏/选择存档/种子与简洁引导形成可理解的入口
- 浏览器完整走通：经营→准备→远征→自动战斗/指挥→三选一→返回→永久成长→保存刷新继续；中英、键盘、窄屏都检查
- 浏览器视觉验收必须包含真实 Canvas 截图与点击，不能把静态美术证明图或服务端渲染测试称为实测截图
- 长期资源、历史收据与日志增长仍需压测；4MiB 导出上限不能在正常长局中变成无法保存。v7无损历史、自动生命周期和空间预算已通过944项整树检查及限定1000循环压测，但手动历史、构筑与完整战役长期增长仍须继续验证；有限压缩不等于无限长局
- 多页存储租约、导入覆盖竞态、旧版本迁移、未知未来版本保护与损坏恢复保持有效
- 数据内容必须经过执行能力验证与构筑实测；当前实验模式不是最终内容认证
- 完整仓库与素材同步、精确版本部署、可重复构建、素材来源记录和最终验收报告需全部交付
