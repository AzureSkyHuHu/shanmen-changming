# 修炼界面接入计划

状态：待世界适配器稳定后实施。不是已完成证明。

## 界面行为

1. 弟子详情展示境界、修为、寿元余量、道伤及当前职务；工作、修炼、休养均以权威命令改变状态，不在界面推进时间
2. 突破先展示完整预览：材料、闭关月数、每月补给、成功率、总体死亡率和逐项风险来源。失败条件死亡率不可冒充总体死亡率
3. 确认的预览携带修炼修订号和基础状态摘要；材料/人物变化后必须重算并再次展示，不能静默接受旧成本
4. 闭关中的取消说明哪些预留材料释放、哪些已经吃掉的补给不退。开始、取消与最终决策都使用同一命令收据系统
5. 寿元将尽和突破决策暂停使用独立修炼暂停原因；关闭面板不能解除该暂停，也不能解除用户自己的暂停
6. 陨落需明确显示永久结果、传承/遗物去向；最终确认只处理已有待定死亡记录，不允许界面自行制造死亡原因
7. 师承只选择真实已学知识和合法存活人物；继承人变化由内核校验
8. 不暴露无条件天赋赠送、战斗处决或底层强制打断。永久树点数/里程碑规则完成前，这些不能伪装成养成功能

## 应用层合同

- ApplicationSession 仍持有唯一 World，新增修炼命令桥接；外层/内层命令ID一致
- 突破预览从同一 World 的修炼、资源、随机流和ID序列读出，不消耗随机数
- React 只订阅有界只读投影；不把整份历史收据/每场战斗日志复制到每帧UI
- 存档导出保留权威暂停与修炼状态，但会话级存储锁不写入世界
- 所有新增文字必须有中文键、英文映射和参数契约；缺失英文逐键回退中文

## 验收

- 选弟子→转修炼→月界增长→预览突破→确认→闭关→风险决策→结果；刷新/读档前后结果一致
- 有工作时转闭关，岗位与资源预留原子释放；取消不重复返还
- 预览后资源被别处使用、存储只读、另一页抢占存档、重复点击均安全拒绝或幂等
- 待定死亡与自定义暂停同时存在；确认死亡不能误恢复另一个暂停
- 中英切换不改预览ID/概率/存档，键盘焦点与关闭面板行为一致
- 桌面/窄屏真实浏览器截图和操作验收仍必需；单元测试不替代它
